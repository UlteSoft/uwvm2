GC / EH performance qualification, 2026-10-05, revision R7

This source implements immutable packed numeric exception tuples, collection-local
adjacent exact-token de-duplication, bounded sweep retirement batches, and a portable
numeric array fill (512-byte seed then non-overlapping std::memcpy for >=2048 bytes).
Reference arrays and overlap-sensitive array.copy keep their existing algorithms.
No AVX2/AVX512/NEON/VSX intrinsic or forced alignment is introduced.

Qualified experimental profile (all TUs must use the same values):
  UWVM_USE_THREAD_LOCAL
  UWVM_EXPERIMENTAL_GENERAL_GC_SLAB=1
  UWVM_EXPERIMENTAL_PACKED_NUMERIC_ARRAYS=1
  UWVM_EXPERIMENTAL_COLLECTION_LOCAL_MEMBERSHIP=1
  UWVM_EXPERIMENTAL_SINGLE_CAS_GC_PUBLICATION=1
  UWVM_EXPERIMENTAL_PENDING_NUMERIC_FUSED_CATCH=1
  UWVM_EXPERIMENTAL_GC_ARRAY_BYTE_PRESSURE=1
These experimental flags are not enabled globally by this change. Fused numeric EH
admits at most 256 payload fields; the non-fused limit remains 64. Indirect throws,
throw_ref and larger payloads retain the native exception path.

The new default-off byte-pressure option charges only packed i64/f64/v128 arrays
of length >=256. The 1 MiB carrier charge is a scheduling hint, not an actual
allocation/RSS limit. It retains the original 4096 allocation-attempt fallback and
all actual guest-entry, root, cohort and exclusive collection gates. It must not
be combined with managed numeric page / sealed cursor or other unqualified profile
variants without testing those combinations. Module-form qualification is separate.

All remote builds, tests, gdb and VTune used /tmp/wasm3-perf-20261004-host/enter.sh.
Test code and products are under /tmp/wasm3-asm-opt-20261004 (host and Docker).
Single-thread measurements use P-core 0; VTune hardware ROI uses P-core 2;
actual shared-memory workers use 0,2,4,6. The cgroup is shared with other builds.
The final 1129-record formal run had no memory.events OOM/max increments.

JIT policy is passbuilder O3, full mode, cache disabled, call-stack none. Compilation
and warmup are excluded from timers and hardware ROI. Timers retain amortized fixed
host transitions, reset/check work and actual GC/EH runtime work. Hot runtime TU is
O3; cold main/host API TUs are O1 -fno-inline-functions for both candidate and control.
Do not describe these executables as an entirely O3 host build.

shared-memory JIT execution is checked separately from automatic multi-thread GC.
Raw-host GC escape, automatic multi-thread GC, reference EH with automatic GC,
all Wasm 3.0 combinations and MODULE builds are not certified by this matrix.

ASan/UBSan: packed fill + schema scheduling oracle 399215 checks each with general
slab on/off; direct numeric tuple 24732 checks; fused bridge and cache lifecycle
581 / 40814 checks; publication, membership/cohort rejection and allocator tests
are preserved in the evidence. New fixtures here need their explicit probe/profile
flags; exact compiler/link commands are saved in the external qualification archive.
No tests were built or executed on the local macOS workspace.

Source-only aarch64 and PowerPC64 BE/LE (POWER8/POWER10) code generation used the
verbatim production fill fragment and LLVM22's full target backend. The installed
LLVM23 ROS SDK lacks a PowerPC backend. This verifies emitted copy/vector code, not
native throughput, the full VM ABI or cross-architecture conformance. No QEMU was
used. Native aarch64/ppc64 hardware and a suitable SDK are required before claiming
performance parity or tuning the 2048-byte/512-byte thresholds there.

Remaining measured costs: many retained roots, scalar allocation/ownership locks,
chunk fragmentation, indirect/throw_ref native DWARF unwinding. Several small/no-

report.html. DRC does not reclaim cycles as a tracing collector does, so its cycle
throughput is not equivalent collection work. Wasmtime copying is reported separately.
No claim that all GC/EH workloads are faster than Wasmtime is made.

The owned inline/reference metadata changes C++ layouts. Cache identity separates
profiles; it cannot make differently built C++ objects ABI compatible.
The new test decoder reads the actual length-prefixed binary cache format, rejects
malformed/duplicate fields, and checks that disabled profiles omit the exact field.

Complete-copy input must provide all 16 bytes of every gc_value carrier, with a
valid source extent and no overlapping destination. Authenticate real reference
fields before allocation, retain genuine owned references before publication, and
normalize packed fields as required. Numeric token-shaped bits must not become
roots. Preserve rejection atomicity, reference leases, and retired-token rejection.
Use standard std::memcpy; no architecture-specific copy intrinsic is introduced.

With GC_ARRAY_BYTE_PRESSURE enabled, explicit/default wide structs and fixed
arrays (>8 fields) reuse the existing 1 MiB carrier scheduling budget. This is an
estimated pressure charge, not a heap/RSS cap or a proof that an object is dead.
Original actual-entry, root, host-escape, exception, cohort and exclusion gates
remain mandatory. Data/element array constructors keep their original scheduling.
The tiny constructor path keeps its previous code to avoid the measured prototype
EH regression. Different collection counts are reported separately from time.

Actual hardware comparison is still pending: the declared matrix has 2124
Hotspots/microarchitecture cells; the clock matrix has 2118 process/interval cells.
Completion markers alone do not qualify them. The independent audits check exact
Wasm/ELF identity, ROI barriers, confinement, P-core affinity, counter validity,
MUX reliability, truncation, oracle checks and verified raw archives.
JIT and warmup are excluded; reset/check work and fixed host transitions remain.
Hot runtime TU is O3; cold main/host API TUs are O1 with inlining disabled.
Per-work timer percentiles and process HWM/RSS are not individual GC pauses or
GC heap size. Allocation source counts are not guaranteed executed allocations
after an engine performs legal optimization. No universal Wasmtime win is claimed.

Threads are tested as a separate proposal alongside Core 1/2/3 feature families.
UWVM's worker fixture shares one module/store and linear memory; Wasmtime's fixture
uses independent Stores/heaps and one SharedMemory. Other native drivers use
private instances for disjoint throughput. Unknown native entry disqualifies
automatic collection; multi-worker results do not certify stop-the-world or
concurrent automatic GC. Do not remove this gate to obtain a performance ranking.
Wasmer worker C API uses Cranelift; its CLI comparison uses LLVM. WasmEdge
interpreter fallback and failed SIMD oracles do not qualify as JIT measurements.
Unsupported vendor feature combinations are explicit exclusions, never zero times.

Wasmtime 49 DRC native C API and its explicit copying collector are distinct rows.
The copying wrapper adds three WASI imports and changes function indices; its
guest work is equivalent, but its whole module is not byte-identical to the C API
fixture. DRC cycle throughput is not equivalent tracing/reclamation work.

All remote commands continue through the original 64 GiB cgroup wrapper. P2
hardware runs are serialized, worker cores are 0/2/4/6, compiles use P6. Temporary
data is stored under Linux /tmp or this Docker cgroup's temporary filesystem.
ENOSPC waits preserve evidence, and data-limit truncation causes recollection with
a lower sampling frequency. Neither increases the cgroup or hardware data limit.
AArch64 vector code generation is checked; the installed LLVM23 SDK has no
PowerPC backend. Earlier R7 PPC copy codegen evidence does not qualify these new
vector changes or native AArch64/PPC performance. No QEMU was used.
