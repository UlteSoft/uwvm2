Wasm 深栈调试修复与验证 — 2026-10-05

uwvm2 与 uwvm2-ros 已同步完成本次物理调用帧上限修复。
真实 Wasm activation 身份链不再截断于 64 帧；64 现在仅是分块存储大小。
增长发生在真实函数进入/宿主桥接路径，块地址稳定并复用高水位容量。
SIGTRAP 路径只比较已有数据，不分配、不加锁、不依靠 DWARF 伪造调用身份。
返回、尾调用、异常展开、宿主嵌套以及 native cursor 的实际 release ACK 保持身份约束。

默认每个身份账本预算为 256 MiB。Linux x86_64 的内联最低预算为 5632 字节，
其他 ABI 由 sizeof 计算。实际预算、分配或身份耗尽会明确失败，拒绝不完整预览。
冷启动宿主接口：
llvm_jit_configure_debug_activation_storage_host_api(std::size_t bytes) noexcept
必须在相关编译计划、执行桥接和发布前配置；不是执行中的调试开关。
只读观察的 frames=0 表示不设固定帧数上限。可恢复检查点的默认 4096 帧预算
仍是独立契约；本次没有宣称 10,000 帧恢复检查点或任意外部 IO 回滚。

CLI 与 DAP：
frames wasm THREAD STOP_ID FIRST COUNT
frames source THREAD STOP_ID FIRST COUNT
每页 COUNT 为 1..128，物理 ordinal 从当前帧 0 开始，total 是真实完整链长度。
例如当前线程 1、stop 42：
  frames wasm 1 42 4096 16
  operands 1 4096 0 64
  locals 1 4096 0 64
恢复执行后必须使用新的真实 stop ID。DAP 自动分页并返回真实 totalFrames。
分页期间重新核对完整停止线程集合；旧 frame/scope 引用会失效。
完整 Wasm 页不可用时明确报错，不再把有限的 bt 窗口当成完整栈。
热替换扫描所有暂停参与者的完整真实链：64 帧之外的活动祖先也会阻止替换；
同一停止点的非活动目标可替换。传统诊断 bt 的 64 帧窗口不再充当替换授权。

精确 typed operands/locals 预览仍以真实 Wasm opcode/safepoint 为边界。
任意 native PC 的当前 Wasm 栈值没有被伪造。保留简短提示：
Note: Last Wasm safepoint snapshot; may differ from current native state.
ASM 操作仍限于认证过的生成 Wasm 上下文，不能借本次改动调试 VM 宿主代码。
DWARF 的 inline/path 预算与物理 activation 深度是不同的限制。

完整检查还修复了：
- fast_io display 列表的裸 char 指针条件表达式导致的编译错误。
- 源帧 DAP 成功返回分支遗漏停止集合复核，以及失败后的有界 bt 回退。
- DWARF 相对目录未结合所属 CU 的 DW_AT_comp_dir，导致绝对源路径断点失败。
  现在按 DW_AT_stmt_list 对应的行号表解析，复制有界嵌入式元数据；
  错误偏移、冲突的共享表目录、嵌入 NUL 和超限路径会被拒绝。
  不读取源文件，不使用调试器进程工作目录猜测，不新增 native PC 授权。
新增路径拼接、输出和参数解析沿用 fast_io；保存并保留其他 agent 的并发修改。
