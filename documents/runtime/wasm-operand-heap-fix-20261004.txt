Wasm operand preview 修复与验证（2026-10-04，V5）

两个本机仓库同步修复：uwvm2、uwvm2-ros。
修复的是 cooperative Wasm opcode stop 的真实 typed operand/local materialization。
本次没有增加任意 ASM PC 上的 Wasm data stack 还原能力，也没有开放 VM 本身的 ASM 调试。

原问题及实现

1. 原 observation-only 预览复用了 resumable checkpoint 的 32768 字节原生工作区。
   1000 个 locals 加两个 operands 会超过该工作区，即使 Wasm 合法且元数据预算足够也会拒绝预览。
   现将 observation-only packet/初始化标记放入实际 debug execution scope 所有的私有堆缓冲区。
   每个实际函数调用只分配一次；大小为 2 * local_count + 16 * max_typed_slots，最小 1 字节。
   编译器在完成所有已验证 opcode site 后确定最终分配常量，再优化、封存和发射 object。
   没有运行时 realloc，不接受 guest 提供的 extent；嵌套调用时各内层 buffer 地址保持稳定。
   实际 return、typed tail、host tail、frame-exiting EH 在原有 activation leave 前释放对应 top buffer。
   内存所有权独立于诊断 ledger；诊断身份配额耗尽不会造成合法 guest 提前退出或错误释放。
   错误的、非 top 的释放请求会失败，不会退休其他 buffer。

2. 原普通执行入口无条件构造 runtime_debug_execution_scope，进入时读取 debug TLS/control。
   现按真实执行 admission 下保持不可变的配置选择 template<bool Debug> 路径。
   false specialization 不构造 debug scope，不安装新 arena TLS，也不执行该构造器的 participant probe。
   selected helper 强制 inline，public entry 保持 noinline，保留原来的 native CFA 边界和 admission。
   dbg 关闭时，生成的 Wasm 中没有新增 arena allocation/release、typed packet stores 或 materialization。
   host entry 仍有一次模式选择，原有其它 host/table debug-control 检查没有全面删除。
   因此这里证明的是本次预览机制的生成代码开销消除，没有宣称整进程绝对零开销。

原 resumable/native restore workspace 仍为 32768 字节；它的 ABI2、cache policy17、原生 owner/provenance
与 pause/generation/source/root 检查保留。observer cache policy 从12升级为13，旧 observer object 不会混用。
私有 arena 的分配/释放仅提供 storage，不产生 query、capture、restore 或 PC 权限。
新增 C++ 诊断与回归测试输出使用 fast_io。
