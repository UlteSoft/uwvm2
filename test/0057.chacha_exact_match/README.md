# Exact whole-expression ChaCha replacement

The existing extra-heavy INT compiler replaced a complete 770-byte Wasm body on a 64-bit FNV hash match and accepted any parameter count at least two. A hash is not an equality proof. This SOURCE patch requires the complete reference expression bytes and the exact ABI: two i32 parameters, no results and twenty declared i32 locals. The ordinary and ROS files retain their separate current preimages and every unrelated control/EH change.

The constant is extracted from the existing hermetic `test/0013.uwvm_int/strict/extra_heavy/uwvm_int_translate_chacha20_megafuse_strict.cc` fixture, not invented from the mega-op implementation. Its reference module is 19541 bytes, SHA256 `9ba47d07d0c58aa8ce6c41c6e77c9911b105abcc47bf13a1010a250af1467104`. Local function46, type14 contains two i32 parameters, no results and one group of twenty i32 locals. The 770-byte expression at [16059,16829) has SHA256 `3f5804aed8cdba9b262e818ccd76122dfc5fd64df23ba261f0d3cbd0a847e764` and the old expected FNV64 value. Source-data extraction is independently recorded in the private packet; it is not official parsing or native qualification.

The original sole fused validator/emitter reaches the function end before this cold optimization test. Extent equality precedes FastIO's complete byte comparison; every local lookup is below the proved exact count22. There is no new Wasm body semantic walk, parser, guest instruction, memory guard, call ABI, native-op implementation or musttail change. The matched opfunc and its three operands plus return stay unchanged. No measured performance claim or demonstrated hash collision is made.

The strict test preserves the existing single reference hit and tiny emitted-body assertion. It then obtains original parser-owned bytes before another module preparation, and compiles five valid shape/content variants: exact2/20; three parameters/20 locals; three parameters/19 locals retaining totalcount22; two parameters/21 locals; and a same-length low-bit constant mutation. Only the exact first variant may contain the mega-op. All five must remain valid; nonmatching functions use the existing fused translation.

Planned native target is `uwvm_int_translate_chacha20_megafuse_strict`, with actual xmake `enable-uwvm-int-combine-ops=extra` and interpreter tail ABI. All builds and execution must be dispatched by the Linux keeper into the existing guarded 64GiB cgroup. Run both products, retain source/build/tool receipts, then check generated ASM of the existing reference kernel and run the existing P-core ChaCha benchmark against the previous exact fixture. Other combine modes must compile without this optional mega-op; a skipped non-extra target does not qualify the new matcher. These tests, official parser checks, assembly and timings have not run in this SOURCE packet.

Primary semantics reference: https://webassembly.github.io/spec/core/exec/instructions.html . A replacement must preserve the complete original instruction sequence and function calling shape, not infer equivalence from a noninjective hash.
