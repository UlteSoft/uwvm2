# Shared Core3 memory.size/grow typed semantics gate

These fixtures are source-only and require the separately reviewed common page semantics candidate plus a fresh coherent SDK/all-runtime/product closure. They do not grant execution admission, prove all Core3 modes are fused, or repair default lazy/tiered raw-decode gaps.

The WAST contains three original modules: memory32, memory64, and mixed 32/64 indexed memories. Ten actual integer assertions check size, portable zero growth and a fixed maximum-one-page failure result. Each zero-growth function stores its actual i32/i64 result in a local, accepts old size or all-ones, and checks that memory.size remains one. Core3 permits growth to fail even when the maximum is not exceeded; zero-growth success is not a standards requirement. Three unused valid polymorphic bodies remain in the original module. Eight unused invalid modules check whole-arity underflow, wrong numeric address width, concrete float values in dead code, and a non-null reference heap bottom that must not be mistaken for numeric value bottom.

`page_semantics_component.cc` directly consumes the shared sequence helper, with 22 checks and callbacks whose one-element bounds are explicit. It checks no-input size, complete grow arity, correct i32/i64 input, synthetic value bottom, wrong concrete width and reference bottom rejection. C++ compilation and standalone module lookup remain pending.

The runner uses official WABT `wast2json --enable-all` only for assembly, groups named modules without changing original memory declarations/instructions, and appends integer assertions using the existing repository wrapper. Both actual full products and pure validator run the original unused invalid bodies; two pure precise-feature-off controls reject the mixed module. Optional Wasmtime uses the same assembled bytes. Configuration `all` is coverage only and does not certify the retained-lazy architecture.

Run only through the sole Linux keeper's existing 64 GiB cgroup and process-owner guard: `run_actual_cli.py <fresh-output> --repository <exact-source> --source-id <computed-source-identity> --wast2json <pinned-official-tool> --uwvm <fresh-product> [--wasmtime <same-platform-pinned-product>] [--ros]`. Use separate output namespaces per product and preserve original logs, actual source/ELF/provider pins, initialized/cold receipts and after-failure diagnostics. No Mac native execution is authorized.

The helper takes the selected address enum minted by the first bounded memory-index decoder. It does not own a byte cursor, scan LEBs, replay raw instructions, change memory access guards or alter register-ring/musttail handlers. Core 3 validation rules are at https://webassembly.github.io/spec/core/valid/instructions.html#valid-memory-size and https://webassembly.github.io/spec/core/valid/instructions.html#valid-memory-grow. Source/Python AST/hash checks are not native, oracle, LLVM emission, assembly or performance qualification.

The zero-growth derivative follows https://webassembly.github.io/spec/core/exec/instructions.html#exec-memory-grow. Mandatory maximum failure remains checked with the original i32/i64 -1 result. Original unused invalid functions and precise feature controls are unchanged.
