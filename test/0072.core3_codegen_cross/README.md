# Core 3 execution and code generation across Linux architectures

This work is in progress. A row is complete only after execution of the exact
target product and inspection of the code generated by that product. CLI
acceptance, compilation, an offline helper, tier publication, and a QEMU run
are distinct evidence categories.

The ordinary product covers interpreter full/lazy (including verified lazy),
LLVM full/lazy and tiered. ROS keeps interpreter full and LLVM full.
Interpreter compile-time axes are combine none/soft/heavy/extra and delay-local
none/soft/heavy; runtime axes independently include each compiled combine level
and delay-local enabled/disabled. An all-enabled binary is useful for initial
runtime checks, but does not replace the twelve exact compile-time builds.
Both runtime and CLI must have matching definitions. LLVM full and tier-2 cover
pb-o1/pb-o2/pb-o3. Lazy covers its actual debug/light/balanced policy interface;
full-policy acceptance does not prove a lazy body used that optimization level.
Tiered checks require evidence of the executing tier, beyond readiness.
Delay-local also requires combine to be active in the translator. A profile
label `delay-1` describes the requested default, not proof that this optimization
ran; combine=disable makes effective delay-local false. Actual fusion selection
needs translator evidence in addition to successful guest results.

`architecture_catalog.py` enumerates Linux architecture/ABI candidates for all
bundled LLVM targets advertising host JIT support: X86, ARM, AArch64, MIPS,
PowerPC, RISC-V, LoongArch64, SystemZ, Hexagon, M68k and downstream SPARC V9.
It records 32/64-bit, endian, MIPS O32/N32/N64, PPC ELFv1/v2 and floating-point
ABI variants. LoongArch32, big-endian RISC-V and SPARC32 have HasJIT=false;
they remain explicit capability gaps. Hexagon needs JITLink while this VM uses
MCJIT/RuntimeDyld; M68k has no supported ELF loader in this VM. BPF advertises
JIT code generation but has a different bytecode host ABI. AArch64_32 is a
Mach-O ABI and does not establish Linux AArch64 ILP32 support. None of these
source-inventory rows are guest test passes. Endianness, pointer width,
floating-point environment, instruction features and library identities are
recorded explicitly.
All compilers, validators, reference interpreters, VM execution, QEMU and
assembly tools run inside the established 64 GiB/swap-zero SSH Linux cgroup,
with owned-process retirement and directory/free-space limits.

Floating-point checks use the [official Core 3 numeric semantics](https://webassembly.github.io/spec/core/exec/numerics.html):
exact bits for deterministic results, signed zero, subnormal preservation,
ties-to-even, conversion limits and traps, payload-preserving bit operations,
and the allowed NaN result sets. Relaxed SIMD checks its permitted result sets
and consistent implementation choices. Ordinary multiply/add must not acquire
an unauthorized fused result. SIMD includes lane order, integer wrap/saturation,
float lanes, conversions, shuffles and memory boundaries.

`nearest_native.cc` also calls the actual interpreter evaluator with dynamic
inputs and checks 42 exact or allowed-NaN results, including signed zeros and
ties-to-even. Canonical NaN inputs require canonical results; other NaN inputs
permit arithmetic NaNs. On LASX, builtin integer lanes carry floating-point bits; the
whole result must be reinterpreted before extracting a float lane. This native
component check complements the real Wasm rounding fixtures. Its named wrappers
permit inspection of the encoded rounding instruction and accidental numerical
integer-to-float conversion. Symbol sizes exclude alignment padding from counts.

`generate_numeric_component.py` generates 5,992 dynamic scalar evaluator checks
from the rational oracle. Its integer wrapper ABI preserves signaling payloads
before sign-only operations on x87. Compile-time assertions distinguish
LoongArch scalar/LSX/LASX and i686 x87/SSE2/SSE4.1 profiles. The optional
`--fixed-nearest-environment` adds 258 nearest checks under downward, upward
and toward-zero rounding, restoring the original environment. These component
runs do not qualify the VM's entry/exit FP environment guard or LLVM JIT modes.
LoongArch LSX uses explicit ties-to-even vector rounding and reinterprets the
integer lanes before extraction. The scalar nearest path uses the existing
integer bit algorithm: scalar FRINT follows FCSR and cannot replace a fixed-mode
operation. Both paths avoid nearbyint calls; actual hardware speed remains a
separate measurement. Keep pre-change R4 results separate from the R5 repair.

Tail tests include millions of direct, indirect and typed-reference transfers,
mutual recursion, different prototypes, spilled parameters and tuple results.
Native assembly must show a jump with no new return link on the guest tail
edge (jmp/b/br/bctr/jr or jalr with zero link, according to ISA). Authenticated
resolver calls, cold traps and policy bookkeeping are classified separately.
Interpreter dispatch and Wasm function transfer both need bounded-stack tests.
An instruction count or QEMU timing alone cannot establish hardware speed.

Every batch binds immutable source bytes, actual compiler inputs, target LLVM
archives/headers and product hashes. Changes by other workers create a new
source cut and do not alter completed evidence. Failed attempts are retained.
No current row in this directory claims full Core 3 or all-target completion.

`compile_variant.py` builds one exact interpreter macro set in all three
translation units, executes its requested full/lazy modes, and binds the linked
product and actual dependency files. The initial 12-build matrix uses host C++
O1 and interpreter-only products. It checks semantics; selected fusion and host
O3 efficiency need separate evidence. Only the new, unshared intermediate
objects from a successfully qualified variant are retired to limit disk use.
Interpreter-only products explicitly define `UWVM_DISABLE_JIT` in every
translation unit; omitting the LLVM selection macro alone is insufficient.
LLVM MIPS compilation also enables `-mllvm -mips-tail-calls`, matching the
product build. The runner rejects a missing option before compiling a threaded
interpreter; removing `musttail` is not a bounded-stack substitute.

`tiered_numeric.py` requires an actual `tiered-full-enter` event for the hot
numeric function, full-module readiness and successful results. Four million
checked calls include ordinary unfused f32 multiply/add, f64 ties-to-even and
SIMD signed-zero/subnormal lanes. A failure to observe entry is a failed tier
qualification even if the numerical results were correct.
The portable cache's private symbol-initialized pointer cells are accepted by
the checked T2 local-target transform only after exact declaration identity,
alignment, volatility, and complete read-only use checks. RISC-V's `lla` cell
address producer has its own exact-shape check. The paired component corpus
round-trips 32/64-bit and both-endian IR, rejects stores and escapes unchanged,
and separately optimizes and executes native MCJIT derivatives. Those IR shape
checks do not qualify foreign native execution; the real T2 runner does.

`truncation_cases.py` covers the eight scalar saturating conversion families
and four SIMD families, including NaNs, infinities, adjacent integer-limit
encodings and the required zero upper lanes of f64x2 conversions. The independent
oracle uses exact rationals and integer clipping. `trapping_conversion_cases.py`
adds 80 dynamic failure fixtures and eight valid-control modules for the eight
scalar truncation families. It distinguishes NaN invalid conversions from
infinity/range overflow, and checks adjacent limits and legal negative fractions
for unsigned results. `run_trapping_conversions.py` requires the exact single
fatal diagnostic and SIGILL/SIGTRAP/SIGABRT termination for each negative case;
timeouts, SIGSEGV, OOM kills, generic error exits and duplicate/wrong trap reports
fail. Controls must exit successfully with checked integer bits. The runner
requires a previously qualified, source-bound product and preserves its actual
dependency hashes; these tests alone do not qualify generated assembly or T2.

is qualified here on x86-64, AArch64, RISC-V64 and LoongArch64; PowerPC64,

The pinned QEMU 10.2.1 LoongArch signal trampoline has incorrect CFI register
numbers: its CFA uses register 2 and its saved PC uses register 64. The
[Linux LoongArch signal convention](https://github.com/torvalds/linux/blob/master/arch/loongarch/include/asm/linkage.h)
uses SP register 3 and repurposes register 0 for the saved PC. The original
provider correctly raises the Wasm memory fault, then crashes while unwinding
through that trampoline. This SIGSEGV is excluded from passing trap results.
