# Private candidate root installation

World preparation now authenticates each relocated reference through the actual unpublished GC staging roster, keeps its cross-store root owner, and allocates stable root_frame records before native TLS publication. The private nonmoving scope installs retained roots, each frame's complete input roots and unused result capacity through real enter_root_frame/publish_root_frame calls. Result capacity starts with live_count zero; it cannot become a returned root merely by being allocated.

Each saved logical thread packet is checked serially on the actual cold calling native thread. Validation starts from its genuine current_root_frames pointer, compares every record with this scope's own stable storage before reading links, verifies exact carrier extents/live counts, and stops at the inherited TLS head. It never traverses or substitutes an inherited caller root chain. Removal uses actual leave_root_frame in reverse order; all records are cleared before candidate engines/stores/source can be destroyed.

maximum_private_root_frames bounds the aggregate record count for ALL packets. A cap that fits only the first packet refuses before installing any record. Frame/record/root-owner allocations remain in maximum_native_payload_bytes. Public results expose diagnostic counts and a chain-restored flag, with no native addresses or executable/root capability.

The complete-instance fixture tests genuine GC cycles, arrays, extern/exn/function values, two paused guest threads, two inherited host root frames, repeated success, early allocation refusal, and late ALL-packet root-cap refusal. The generation-2 nested fixture tests root-to-leaf caller/child packets and inherited TLS on both actual pause episodes. Native instruction and unwind qualification is recorded in the R53 report.

This is actual cold candidate TLS installation/removal, not enrollment of restored workers, live GC-store publication, whole-instance execution restore, or external I/O rollback. Future startup workers must install their own thread-affine scopes under genuine closed startup ownership. ASM debugger access remains limited to guest Wasm/JIT context.

The cold preparation now also creates a genuine private FastIO native worker for each prepared packet. All fixed worker records and native wrappers are charged/preallocated before launch. Each worker installs and validates its own actual TLS prefix, acknowledges through an atomic release/acquire gate, and keeps its scope alive until all workers have acknowledged. The coordinator cannot supply a callback, root pointer, native thread ID or startup permission. Every worker revalidates its still-live prefix before same-thread LIFO removal. The coordinator releases and physically joins every actually started worker (also after a later launch failure) before candidates can be destroyed.

The default maximum_private_root_workers is 256. An insufficient entire-cohort quota or native storage budget refuses before any OS creation with worker_root_preparation_declined. started_private_root_workers, enrolled_private_root_workers, joined_private_root_workers, private_worker_cohort_held and private_worker_roots_restored are diagnostics only. This is private candidate native-thread root enrollment, not published restored-worker execution enrollment: no execution/GC admission lease or debug activation is forged, and no candidate entry runs. Blocking join of finite private bodies is not a bounded restored-world retirement credential.


## Private debug startup contexts

The same real private root worker now owns a genuine participant in a separate world-owned pause domain, a preallocated activation ledger, a checkpoint shadow ledger bound to the actual candidate resumable profile, and an operand workspace stack. Complete controller backing, fixed ledger objects and packet storage are charged before any OS thread is started. No current paused controller is reused.

Each actual worker requires fresh debug TLS, publishes only its own native borrows, and verifies that both ledgers are healthy and empty. No saved frame is inserted as an executing activation. The coordinator checks every real participant and distinct ledger owner while the entire root/debug cohort remains live behind the release gate. Roots leave first; on that same thread all debug borrows are cleared, the empty activation ledger is poisoned, and its participant unregisters before physical FastIO join and context destruction.

prepared_private_debug_workers, enrolled_private_debug_workers, private_debug_cohort_held and private_debug_tls_restored are counts/status only. This private startup rehearsal provides no current execution/GC admission, native stack registration, guest activation, source/code publication or restore credential. Published restored-worker execution enrollment and whole-instance restore remain separate unfinished work. Native instruction/unwind fixtures check genuine successful cohorts and zero-work launch on whole-cohort quota/payload refusal.
