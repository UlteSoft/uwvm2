This candidate implements the first real saved-execution continuation of a full LLVM-JIT function. It is PRIVATE source until reviewed and built by the sole guarded Linux keeper. It has not been run or compiled locally. It does not assert complete-instance restore, arbitrary Core3 resume, reverse execution, deterministic replay, or cross-platform acceptance.

The fused validator/translator constructs each exact semantic layout before consuming its opcode. The original LLVM body gains typed logical landings: a resume edge restores original-index initialized flags and local values, and merge PHIs replace the compiler’s live operand handles. The selected instruction then publishes precise GC roots and its real typed packet. After verification, a same-module IR clone changes only five compiler-owned SSA zero inputs into hidden continuation arguments. The ordinary public Wasm ABI remains unchanged; no second decode or validate pass is introduced. A separately verified host ABI wrapper calls the cloned body. Normal null-profile compilation emits no selector, landing, clone or wrapper.

The continuation dispatcher first resolves both actual canonical owner registries and checks that the original monotonic participant has actually retired. A completed stop ticket, aliasing shared_ptr, matching numeric ID, DWARF entry, instruction display record, or checkpoint file cannot supply this authority. Under a fresh real runtime execution lease it checks the source owner, profile owner, module/function/code generation, sealed plan owner and current publication identity. The address comes only from actual LLVM engine finalization and the complete native symbol resolution loop. The first execution slice accepts scalar, null and i31 carriers from the real owned capture; it does not carry unrooted native GC pointers across time.

The fixture uses Core3 nondefaultable i31 locals, a live i64 operand, and preceding memory/global writes. The actual runtime test must capture a real parked function, reject premature continuation while its old participant exists, retire the original execution, and resume from that exact opcode. The old prefix must not run again. A later real guest memory write must remain unchanged by this execution-only adapter, demonstrating that it does not falsely claim resource rollback. The result is checked against the completed ordinary execution. Foreign owner aliases, invalid result extents and retired code generations must fail without modifying the result buffer. Run both products with instruction and unwind stack strategies.

The private native ABI is void(u64 site, ptr owned_packet, uintptr packet_bytes, ptr original_flags, uintptr flag_count, uintptr result_address, uintptr result_bytes). Selected entry/landing IR first requires the actual Module DataLayout to be nondefault, to match the runtime pointer width, and to match native byte order; this check precedes allocation or pointer IR. The ordinary null-profile return precedes that check. Component tests must install a real native target-machine layout and reject empty, foreign-width and foreign-endian layouts without adding dispatch IR. Every packet/flag byte advance follows complete count, null and PTRDIFF_MAX checks; input marker validation precedes any load or state mutation. Nondefaultable uninitialized local slots never execute a payload load. No native PC, native stack image or return address is accepted from saved DATA. The profile cache tuple policy revision changes from 5 to 6; wire schema3/logical schema1 remain unchanged because the portable state format is unchanged. Existing process-bound debug bridge IR still makes object caching unavailable. Adding the new symbol does not enable cache acceptance.

The complete VM continuation design uses the existing state3 logical IDs and needs these connected producers, not success-shaped placeholders:

1. Build all memory/table/global/segment and typed GC/exception graphs in a detached unpublished instance generation. Fix up references only through the private staged owner after validating the complete graph. Store roots must remain owned until atomic publication.
2. Capture exact active control labels, saved block parameters and operand prefixes from the same authoritative walk. Restore every live LLVM handle needed by the selected CFG edge; structural label/PHI metadata is part of continuation correctness, not debugger display.
3. Capture real awaiting-call continuations before entering the callee, including caller roots, exact declared results and normal/exception after-call sites. Resume the leaf once, then feed its typed outcome into each parent without repeating earlier calls. Tail calls reset the logical activation with the real continuation identity while retaining genuine musttail code generation.
4. Own pending exceptions as tagged logical objects with payloads and complete active handlers. Continue semantic catch selection and cleanup from those typed states. C++ catch pointers and native unwind frames are never portable continuation state; native unwind remains the executing engine’s mechanism for fast propagation and readable stack reporting.
5. The coherent manager must close guest/host admission, prove one complete current-ticket cohort, prepare all detached state and continuation entry owners, retire old native activations, and atomically publish the replacement generation. A failed preparation must leave the current instance intact. One saved leaf adapter is deliberately insufficient to commit this transaction.
6. Resume every captured VM thread using its logical state and restore shared-memory identity, waits and scheduler state. Deterministic replay additionally records host results/errors and guest-visible atomic/wait/notify event order. WASIp1 environment restoration attaches its own versioned safe logical-resource adapter and never injects a raw host FD or half-completed syscall into a restored Wasm frame.

Source and assembly debugging are observations; their PC/line mappings cannot grant restore capability. Checkpoint binding must cover the entire original Wasm including custom sections, all participating modules, feature policy, exact uwvm build/version, backend/provider, schema, compilation profile and actual accepted cache input/ABI bundle. A changed module, function replacement generation, producer or ABI policy requires new identity and code resolution. Whole-state acceptance remains false until those producers and the atomic commit path are qualified.

Reserved-mode performance must be measured against ordinary full JIT with the same workload and CPU lane. The ordinary zero-selector body should fold its unreachable resume CFG after optimization; this is a claim requiring actual IR/assembly inspection. Current opt-in packet materialization still occurs at every selected opcode, so idle-reserved overhead is not yet accepted. The next optimization must make typed copying a genuinely requested cold path without bypassing the real observer/request-before-park order or precise-root safety. No extra memory-access guard, lock or software check is added by this slice.

Core3 defines typed store objects and logical execution state; LLVM maps low-level liveness and supports same-module cloning. OpenJDK’s owned vframe materialization/unpack and explicit pending-exception handling informed this design. This is an implementation design inference, not a claim that any of these sources supplies this project’s restore authority or ABI.
