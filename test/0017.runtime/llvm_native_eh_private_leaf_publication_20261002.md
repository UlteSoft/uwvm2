# Private numeric EH leaf: actual publisher source candidate

2026-10-02. The separate exact-1 `UWVM_EXPERIMENTAL_NATIVE_EH_PRIVATE_LEAF`
candidate now implements an actual full native publication transaction. It is
default off; the initialized canonical source also needs its separate, initially
false native administration request. This source has not been compiled or
executed. No native pass, speedup or industry comparison is claimed. The immutable
Stage3 staging v1, observer v2, setter and GC snapshots remain separate.

The first runtime admission requires LLVM full, explicit native exception
dispatch, supported unwind generation, one actual initialized module and no
imports of any kind. Debug management, numeric pending plans, pre-link callbacks,
object-cache replay and parallel private object emission decline this candidate.
Unsupported cases use the original standard implementation. The actual complete
fused result, joined workers, retained source/control blocks and final linked IR
produce staging provenance; observations or request bits alone grant no code
permission. No second Wasm traversal, validation pass or body clone is introduced.

Before materialization, the publisher keeps the exact original public IR/context
and builds its private candidate in another context. Internal selected clones
retain native cleanup, personality and UWTable, gain NoInline, and never gain
nounwind. Final actual clone uses must be genuine direct CallBase nodes with the
original versioned identity, caller, argument types, FunctionType and calling
convention. A single compiler-owned `llvm.compiler.used` array keeps the exact
private ABI across LLVM's dead-argument/return elimination. This metadata has no
runtime load, store or alias use and publishes no guest-visible entry. It is
created once after all selected clones. The publisher checks its exact appending
linkage, `llvm.metadata` section, initializer ownership, address space and count;
each selected clone must occur exactly once. Only that non-executable metadata
use is exempted from call verification. Every executable selected identity
occurs once; no new/address-taking/indirect caller is admitted. The complete
preserved selected set is bounded to 4096 for
this first publisher; verification stores at most 4096 five-integer identities
and has a bounded quadratic duplicate/witness comparison. Legitimate IPO that
changes a private signature, duplicates/inlines a witnessed caller or removes a
selected call currently declines, rather than pretending it preserved this
initial proof. `NoInline` alone and LLVM 23's `NoIPA` do not freeze this ABI.
The retention metadata is source preparation; actual post-IPO ABI, symbol/FDE
and runtime controls must still qualify it. No native success is inferred from
the LLVM pass source.

The actual engine binds the exact four-uintptr versioned no-trace bridge before
relocation. Only candidate engines request the new cold CFI/object observations.
Private sizes come from a separate ELF `ELFSymbolRef::getSize()` / explicit
`st_size` path, relocated within the actual loaded text section. They never use
ordinary `computeSymbolSizes` next-symbol estimates. Initial private publication
therefore declines COFF, Mach-O and other formats; ordinary platform unwind,
exception handling and diagnostic ranges remain unchanged. The original memory
manager first registers its normal relocated EH frames, then synchronously parses
those actual bytes. Each clone requires an FDE at its exact code start covering
its complete explicit loaded symbol size. Both observations cap their records
at 4096; CFI spans cap at 256MiB. Errors or candidate-owned allocation failure
decline this private experiment without undoing original CFI registration.

Only after actual ABI, every selected call, symbol, extent, FDE, current source
control block and real runtime generation agree does the full publication own
the engine/context/private source owner. The original listener commits ranges,
private clones receive original logical module/function PC mappings, and public
function-index/table/ref.func targets remain their ordinary public entries.
Engine/CFI retire before context and private source/tag metadata at actual
execution stop/drain. The existing terminal process-exit intentional engine leak
also retains its private source owner. Failed private materialization destroys
its listener/engine/CFI first and restores the original public IR, including
public caller to public leaf edges, before normal LLVM materialization retries.
It never retries Wasm decoding/validation or publishes failed native ranges.

Any present private publication owner, including a stale/malformed one, blocks
configure/observer installation, prepare-debug, native-step/stack/bitmap metadata,
source/activation metadata and replacement prepare/commit. Checks use the existing
publication guard and introduce no reverse publication-to-pause-domain nesting.
Future mid-run attach requires a separately implemented real drain/rebuild; this
prototype rejects it. The publication host view is read-only data: a positive
binding requires committed current generation, exact record/source control block,
the same live engine/context and recorded actual full-validation epoch. Neither
view integers nor a raw host request mint a binding.

`llvm_native_eh_private_leaf_publication_runtime.cc` uses actual owning CLI
parse/init and `full_compile_and_run_main_module`, with the new two-tag Wasm
fixture encoded once for the official validator, Wasmtime and both products.
Its private/public/rollback/debug-decline/instruction-decline controls exercise
both payloads, public and ref-retaining callers, source/generation reset and
management rejection; serial and two-worker fusion are separate cases. A
product-absent CFI-failure seam rejects only after every real FDE/extent passes;
its retirement notification occurs after the native lexical scope closes and
original IR is restored. The separate uncaught invocation must exit through the
original detailed report with payload 49 and a nonempty original throw trace,
not through a fixture PASS. Existing strict late-invalid fused tests remain
mandatory, and any unrelated allocation/configuration failure is not a Wasm
standard rejection.
