# Core 3 lazy typed-select boundary correction: source candidate v2

The ordinary LLVM lazy callee-discovery helper treated typed-select's result vector as one-byte wasm1p1 value types. Core 3 binary `select` instead carries a vector of complete valtypes: reference valtypes may contain a signed-33 heap index, and current GC/exception shorthand types extend the legacy enum. The source consequently stopped discovering later callees for these grammatical bodies. No native module refusal or speed improvement is asserted.

The helper now calls the same `recursive_binary_details::reader::value` used by wasm3's context-aware carrier decoder. It does not classify a concrete heap from an empty synthetic module or impose a fake SIZE_MAX type-table bound. Only syntax and byte boundaries are observed. Actual type-index membership, mixed type kind, feature gates, result arity, operands and translation remain in the normal fused compiler. A failed later vector entry never commits outer code_curr. The old whole-vector byte-count advance is removed; the local cursor advances only by each complete decoder-proven length. Every new movement has a before/after range diagram.

`llvm_jit_lazy_core3_value_scanner.cc` has 40 expected grammar/boundary checks: all current one-byte valtypes, nullable/non-null indexed references, padded index128 and maximal-u32 s33 spelling, exn/struct/func/extern heaps, grammar-only zero/multiple result counts, malformed/truncated/overflow/negative-padded heap failures and a direct call immediately after a multi-byte type. The empty runtime module is not validity or execution authority. The existing EH component remains unchanged at 26 checks.

Six new complete WAT fixtures cover nullable/non-null struct select (including observable field readback41), nullable indexed function select, exn/noexn select and rejection of nullable operands for a non-null result. Every _start reaches a later direct call returning47. The decision-comparison runner includes `lazy-select-scan-{struct-nullable,struct-nonnull,function-nullable,exn-nullable,noexn-nullable,nonnull-rejects-null}` for official same-byte validation plus pure/int full/lazy/LLVM full/lazy; ROS has no lazy backend and runs its supported three entries.

The immutable v1 EH snapshot is retained. This v2 snapshot includes both source-confirmed boundary fixes, the existing raw test API adaptation and all ten complete WAT cells. Python AST and source hash checks are only data/source checks. No component was compiled, no WAT parser/VM was run locally, and no all-opcode equivalence or runtime/performance pass is claimed. Keeper should compile all three ordinary scanner components, then official parse/validate and the focused ten cross-mode cells against a freshly aligned source/runtime before broader tests.

Primary specification: [Core 3 binary instructions](https://webassembly.github.io/spec/core/binary/instructions.html), [Core 3 binary types](https://webassembly.github.io/spec/core/binary/types.html), [Core 3 instruction validation](https://webassembly.github.io/spec/core/valid/instructions.html). The references were read as WebAssembly3.0 dated2026-10-02; these corrections do not require a whole-body prevalidation pass.
