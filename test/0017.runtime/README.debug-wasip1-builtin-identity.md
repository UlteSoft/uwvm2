# PRIVATE SOURCE proposal: builtin WASIp1 provenance

The native loader still inserts the same exact builtin module. For a real immutable debugger source only, its concrete insertion now records an unforgeable canonical identity. The actual initializer seal captures the final native vector extent/base, exact actual wrapper and implementation identity, and unified typed registry membership. A later cold lookup requires the real validated module ID/member/epoch and actual imported-function record. It returns a bounded, pointer-free copy of the known compile-time WASIp1 tuple signature and function index, plus a FastIO SHA256 of the entire ordered known names/signatures (so optional tuple changes or equal ABI shapes cannot alias); no imported name or exported shape authorizes a provider.

The identity owns provenance **only**, not the native implementation. The existing local_imported wrapper remains unique-owned and its constructors/destructor/copy/move/call methods are not changed. Every positive lookup therefore needs the real maintenance/closed-host/cohort/source protection for the entire lexical borrow; this helper is not permission to use a host pointer beyond that protection. Persisted checkpoints retain DATA only. Native provider reset/new insertion, vector relocation/growth, source retirement or a changed publication epoch invalidates the lookup. Old WASIp1 implementations, strings, IO and fast paths are untouched.

This packet does not change census's current native-import refusal. The checkpoint owner must narrowly integrate genuine returned DATA into its existing actual whole-world capture/restore design after evaluating that design's maintenance lifetime; opaque native/DL/weak providers continue to require real adapters. WASIp1 environment/FD recovery and external side effects remain separate obligations, not claims made by this identity.

New DATA test checks the unparsed source refusal and private constructors; the modern WAT fixture imports and actually calls args_sizes_get. Neither has been compiled or run in this SOURCE packet. Positive runtime verification must execute the actual owned loader/initializer/fused validator, inspect this descriptor under the genuine current transaction, compare the actual import signature, and deny stale/forged/rebound providers. No native, WAT validation, cross-platform, GC or restore PASS is claimed.

No-EH compatibility is a separate actual component: `debug_wasip1_builtin_noeh_loader.cc` starts with the real empty native registry and unmapped/non-debug source, invokes the sole genuine typed builtin factory, and checks that the original native insertion succeeds. Compile fresh with `-fno-exceptions` and run `--require-no-exceptions` via the original Linux cgroup, both products. This must print `cpp-eh=0`; a normal-EH run does not qualify no-EH compatibility. It does not claim native closed-host/cohort/N capture or issue a provider identity. Disabled WASIp1 configurations are not a pass. The producer keeps the ordinary insertion enabled independently of debug provenance's C++ EH availability.
