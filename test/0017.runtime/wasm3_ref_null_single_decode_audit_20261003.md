# Core 3 function-only ref.null single decode candidate

This source revision removes the second successful heap scan in the int and LLVM function-only `ref.null` branch in both repositories. Pure wasm3 already uses the same bounded-scanner-success / diagnostic-wrapper-on-error pattern. It preserves decoded heap, feature ordering, nullable carrier, exact function witness, operand stack construction, emitted instructions and the existing error policy. No body prevalidation is added.

The bounded scanner commits only a complete, enabled and in-range heap. A failure leaves the cursor at the original heap byte. Only this cold failure calls the existing wrapper again to construct its original typed parse/validation diagnostic; immutable source bytes cannot change between these two failed scans. The successful path reads once and uses `decoded.heap` and `decoded.carrier` directly. No new runtime authority or pointer ABI is introduced.

`ref_null_single_decode.cc` uses actually parsed/initialized legacy function-only type storage and an independently selected code-validation feature policy. It does not fabricate owners or edit retained runtime metadata. Its pure and fused comparisons cover abstract func/extern, concrete and multibyte function heaps, padded positive indices, non-null narrowing, wrong hierarchy, disabled function references, unknown indices, illegal padded abstract heaps and overflow. The raw bounded-reader cases separately cover empty and truncated immediates; they do not claim initialized-module authority. Positive null-to-nonnull cases are validation-only, since execution must trap on null. The existing callable `_start` WAT sources check a declared non-null function and nullable typed-select followed by real `call_ref`; one reachable wrong-result function remains invalid. The runtime comparison runs both ordinary scoped policy and GC-off policy.
