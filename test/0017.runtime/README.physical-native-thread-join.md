# Physical native-thread join — private SOURCE proposal

This packet changes no live file and has no native compilation/execution evidence. ROOT alone may publish an exact preimage match and admit builds/tests. It is an independent cold owner-retirement API, not completed CLI shutdown.

`fast_io::native_thread` is `pthread_thread` on POSIX, `nt_thread<false>` on ordinary Windows, and the distinct `win32_thread` only for `_WIN32_WINDOWS`. Existing `join()` blocks; POSIX `joinable_`/`id_` are private. An external native join followed by ordinary join/detach or private-state copying is invalid. A body-return flag, `notify_guest_exit`, execution lease count zero, or a second joiner thread's flag never supplies physical thread retirement.

The added `try_join() noexcept` returns joined/pending/not_joinable/unsupported/failed with native error detail. On Linux glibc it invokes the exact noexcept asm ABI for `pthread_tryjoin_np`; only native success clears the wrapper's fields. The Linux branch explicitly excludes `__UCLIBC__` and `__BIONIC__`; no generic opt-in macro can select another provider. uClibc-ng defines `__GLIBC__` compatibility macros, while its LinuxThreads tryjoin uses a logical `p_terminated` flag and asynchronous manager request before actual kernel exit. musl v1.2.5 tryjoin may enter an unbounded join during its exit transition or thread-list synchronization. These are concrete source reasons to reject the broad R1 guard, not mere missing platform metadata. No musl/uClibc/Bionic native-join success is claimed. Unknown POSIX providers return unsupported, retaining their owners. There is no blocking fallback, detach, raw clone or synthetic ACK.

On actual NT/Win32 aliases, a zero-timeout wait inspects the owned native thread handle, and fields are cleared only after successful wait plus real handle close. Failure preserves the owner. This source design still requires Windows SDK/linker/FastIO/actual VM qualification; it is not a Windows result.

`utils/thread/native_thread_join.h/.cppm` adds a synchronous management borrow with a steady-clock deadline, no retained pointer/callback, and no dependence on application exit flags. impl.h/.cppm include/export it. The borrow always returns pending, error or unsupported without destroying the actual native_thread or its strong VM/controller/code owners. The caller must retain all of them until genuine joined. This wrapper does not close providers, force guest cancellation, drain LLVM compilation/cache workers or prove full VM cleanup. No thread owner may be destroyed on a pending return.

The utility handles other native-thread backends without requiring a nonexistent try_join member. The finite component targets the qualified Linux glibc/NT aliases: a real thread's body returns, then its actual C++ thread-local destructor waits on a host gate. The join must remain pending and ownership intact during that gate. Releasing the actual TLS gate must permit actual native join before any successful ACK; a TLS-completed marker is intentionally set before its final member destructor. All setup failures release the gate. If native join still fails, the component uses explicit failure-only process containment, never a cleanup claim. ROOT keeper must impose an outer wall deadline and inherited 64 GiB cgroup; all component execution remains pending.

No existing constructor, move, destructor, join/detach, object layout, memory-access hot path or ordinary worker-pool call was changed. Performance and noEH/header/module compilation still require native qualification. This is SOURCE risk assessment, not measured performance.

## Remaining platform work

FreeBSD 14.3 source/header/export maps provide peek/timed join and do not export pthread_tryjoin_np; a separate source provider proposal is being prepared. This minimum R2 deliberately declares no unknown BSD ABI and enables no BSD provider. macOS publicly documents blocking pthread_join; pthread_mach_thread_np alone supplies no termination proof. A future Darwin provider must retain an actual Mach send right associated with the owned pthread, authenticate a genuine kernel death notification, and prove its subsequent join cannot wait for outstanding TLS/termination work. Body flags, run_state snapshots or raw port integers cannot qualify it. Other BSD/libc/architectures are explicitly unqualified. This is incomplete work, not feature acceptance or a substitute for the required all-platform implementation/testing.

## R2 source evidence and limitations

R1 remains immutable and is rejected for publication: `__GLIBC__` alone admits uClibc compatibility providers, and a generic opt-in cannot repair a provider whose implementation still waits or reports a logical exit. R2 changes only this Linux admission and the matching actual TLS fixture guard; all helper signatures, Windows methods, class layout and ordinary join/detach behavior remain unchanged. Compiler/SDK/architecture/library execution is still pending ROOT keeper. The steady-clock management deadline bounds repeated pending polls; it is not a hard real-time guarantee for internal OS/libc synchronization or scheduler service.
