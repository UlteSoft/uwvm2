# Deep original path value sources

`set wasm global MODULE GLOBAL PARTICIPANT from handle SESSION HANDLE [path EDGES...]` and the corresponding table form use an existing current path DATA label. The complete original root and owned path are copied only after exact controller session/current stop/complete cohort generation matches. Suffix extent is checked against16 and the total against4096 before any growth. This operation issues no additional path label and retains no native owner. After that extraction the ordinary original-root mutation path reacquires the genuine current cooperative cohort, canonical captures, tracked-host closure, actual N/GC root exclusion, immutable member source, current generation and publication. An unresolved handle is always rejected by the native API itself.

Success calls the existing real `advance_stop_identifier_locked`, so all prior source/path labels are invalidated. Native ASM stops, wrong sessions, never-issued or predecessor handles, changed stop/epoch/ANY member generation, and paths beyond4096 fail without writing the target. The original path remains intact on suffix failure; no label or persistent path allocation is committed by value extraction. The management command keeps the existing512-byte bound; iterative `path extend` supplies long paths.

Qualification is deliberately divided. `debug_wasm_mutation_data.cc` and `debug_wasm_path_data.cc` test grammar/session/index quotas using detached DATA only, including exact4096 and4096+1. `debug_wasm_mutation_runtime.cc` enters two genuine LLVM-full guest participants and creates genuine ledger handles only after each real query, then tests actual4096-edge cyclic struct traversal, final packed scalar assignment, invalid last field and4097 rejection under the existing authenticated manager; its direct native unresolved-handle input is refused. Its local episode key is DATA, not a controller stop credential; the genuine ticket and captures authenticate all native work. This runtime fixture does not claim to test controller CLI routing, sole-foreign-root GC reclamation, or whole-instance restore. Run both products, both instruction/unwind, only via the original Linux64GiB keeper. Big-endian DATA requires the actual `--require-big` target; it is not a byteswap simulation. All new source is uncompiled until the keeper records fresh results.
