# Core 3 GC policy from encoded declarations, not parser selection

Source confirmation: `define_parse_core3_complete_type_section` handles direct 0x60 types when GC is enabled, then sets `section.requires_gc=true` unconditionally. A real MVP module parsed and initialized with GC enabled therefore fails when only the validator/compiler GC policy is narrowed. This test first uses fully enabled parsing/initialization of actual wasm-tools bytes and never edits retained types, source buffers, authority or runtime owners. Both pure APIs, int full, ordinary int lazy materialization, LLVM full and ordinary LLVM lazy materialization receive the independently narrowed policy. ROS uses its supported full paths. The fixture prints every actual result and returns failure for normative mismatches; an expected before-fix failure is not a standard PASS.

First actual before run only `gc_two_phase_mvp.wat` after official parse/validate. It must be accepted with validation GC on and off, and its type-section requirement is false. Capture the actual metadata, parse-domain feature error and each materialization result. Production has not been changed in this source-only regression package. Subsequent official cells distinguish pre-existing func/extern and typed-function references, independently enabled exception references, encoded rec/sub/struct/array types, and declaration-only GC values in locals/tables/globals/elements/bottoms. An exn declaration needs exceptions, not GC. All modules are normative-valid under the fully enabled policy. Oracle encoding must confirm explicit rec/sub wrapper preservation before metadata expectations are used.

After the actual before reproduction, the narrow production design is:

- Classify the complete type section from its bounded decoder-proven rec/subtype prefix offsets and validated rich heap declarations. Explicit 0x4e/0x4f/0x50, struct/array kinds and true GC heaps need GC; direct numeric/func/extern/exn-only 0x60 types do not. Byte values inside a LEB/signature must not impersonate an outer prefix. Reuse one Core 3 rich-value classifier; never classify GC by its projected 0x70 carrier.
- Retain parser-section GC requirement booleans for table/global/element definitions and imports at their existing checked type-decoder success points. Locals already retain exact core_type/has_core_type, including zero-count runs; inspect those only under narrowed GC policy. Copy aggregate metadata through initializer/runtime storage and the two existing runtime-validation module adapters. Do not add a body validation pass or body rescans.
- Extend the shared wasm3 declaration-policy helper for narrowed GC policy and route pure/int/LLVM eager and lazy declarations through it. Its fully enabled early return remains ahead of any declaration walk. Preserve GC/EH/function-reference independent gates, canonical type/context bounds, and the original body-pointer diagnostic borrow. An unknown/unretained rich type cannot grant a GC-off success.
- Keep old pure wasm1p1/wasm2 validators untouched. Parser feature headers may change because they retain actual encoded requirements. Initializer narrowing must also reject GC declarations before runtime publication. Public guest ABI/layout, mutable synchronization, roots, collector permissions and default feature switches stay unchanged.

Proposed production paths are parser wasm1p1/features/types +element_section, parser wasm1/features table/global/element storage flags, validation/standard/wasm3 value_immediate+declaration_policy+validator, initializer/runtime storage, both existing runtime-validation adapters, int context/lazy declaration gate and LLVM single-function declaration gate. Header/module imports for any shared helper must be paired. Root must review this design before production edits; actual before reproduction must precede the fix.

Native/sanitizer/LLVM materialization and execution are pending. Source-only syntax/hash checks do not establish standard conformance or performance. This component compiles actual bodies; it does not execute the Wasm entry. It does not change v6 or any older immutable snapshot and must not overwrite later checkpoint shared LLVM fields.

Primary reference: [Core 3 binary types](https://webassembly.github.io/spec/core/binary/types.html) and [type validation](https://webassembly.github.io/spec/core/valid/types.html). Independent proposal switches are product policy; they must retain actual syntax requirements across reuse of the parsed module.
