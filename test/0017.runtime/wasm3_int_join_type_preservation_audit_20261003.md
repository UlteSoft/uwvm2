# Core 3 reference types survive int control-flow joins

The register-ring compiler previously replaced the specification operand stack with a physical codegen snapshot at four if/else/end restoration sites. Its codegen push helper records only the ABI carrier. Consequently an exact `(ref i31)` prefix below an empty if/else lost its heap and was interpreted as func because both use carrier 0x70. This is an actual source-level semantic defect, independently traced through local.get, codegen push, saved if-entry state, else restore and i31.get validation. Native confirmation is still pending.

The v5 candidate changes the sync helper in `single_func_context.h`; v5-r2 also passes the existing actual incoming-edge witness at its four callers. All four callers have already truncated the specification stack to the frame prefix and pushed the declared start tuple (else) or result tuple (end). That stack remains authoritative. The helper checks equal size and concrete carrier layout only for a physically reachable snapshot, restores only the physical codegen snapshot and retains the original byte-count/max-accounting. It never compares exact metadata against the physical snapshot, never copies an actual input subtype over a declared parameter/result, and does not use placeholder unknown/reference-bottom carriers as type proofs. Codegen push/emit routines, guest data and ABI are unchanged.

The four callers are the explicit else path, an implicit-else merge after an unreachable then arm, a then-arm merge after an unreachable else arm, and a generic branch-to-end merge. The first caller follows `operand_stack_truncate_to(if_frame.operand_stack_base)` plus `block_push_types(if_frame.start, ...)`. The other three follow `operand_stack_truncate_to(base)` plus `block_push_types(frame.result, ...)`. Their existing reachability/parent-polymorphism conditions remain intact. The layout-check witnesses are respectively `if_frame.codegen_entry_reachable`, `frame.codegen_entry_reachable`, `frame.stacktop_has_then_end_state`, and `frame.stacktop_has_end_state`. A nested unreachable block can end with a declaration-typed result while no execution edge reaches it; v5-r2 does not assert that its synthetic validation tuple exists in a dead physical snapshot. No witness is a semantic type authority and none changes emission or control flow.

Eight reachable WAT controls check i31, struct and typed-function prefixes, all four restoration branches, a declared-any block parameter/result that MUST NOT retain the more precise input i31 type, and an unrelated funcref that MUST NOT become a struct. `_start` supplies real values and checks result47 for valid modules; invalid probes are reachable. The C++ component accepts official-assembled file bytes, actually parses/initializes each source, and compares pure validation with by-reference plus three register-ring layouts. It validates/compiles; actual Wasm execution is separately performed by the existing runtime CLI matrix. No fabricated module owners or synthetic permissions are used. Three v5-r2 controls additionally check a dead-execution but valid-validation i31 tuple through explicit/implicit else and the invalid corresponding any tuple. Their exported `_start` avoids executing the trapping probe; the compiler still validates and translates every probe. The component supplies the complete function index (retained imported-function prefix plus bounded body index) to the pure validator.

`ref_join_combine_delay_matrix.json` fixes all 32 omission/definition vectors for combine/heavy/extra-heavy and soft/heavy local delay. Defined-zero is not substituted for omission. Each source consumer must use its actual recorded vector. Compile source/layout checks are not runtime, ASM, musttail or performance evidence. Initially run the default and currently used vector locally focused on these fixtures under the sole Linux keeper, then complete all32 vectors without blocking unrelated development. The component's expected int count for all11 fixtures is 243; it is a static expectation, not observed output.

Source-only: no native compilation/execution, WAT assembly, VM run or performance measurement happened locally. v3-r2 blocktype and v4 ref.null archives remain immutable. The pointer diagrams on borrowed stack entries prove both array bounds before access; this helper does not move a body cursor.

Primary rule: [Core 3 control instruction validation](https://webassembly.github.io/spec/core/valid/instructions.html) and [official validation algorithm](https://webassembly.github.io/spec/core/appendix/algorithm.html).

v5-r2 is a source-only correction to the new v5 consistency assertion, not a newly observed native failure. The v5 archive remains immutable and has no native qualification. The new assertion is limited by the compiler's actual execution-edge flags; the specification stack remains declaration-typed even on dead execution paths. No old wasm1p1/wasm2 pure validator was changed.
