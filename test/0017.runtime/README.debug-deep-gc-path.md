# Deep original-index GC paths

The controller-owned ledger stores only original root selectors and immutable integer member paths in one authentic debugger management session. It retains no native, GC, source or compiled-code owner. Every create, extension and member page uses the existing real current typed captures and complete stopped cohort -> actual host closure -> N GC exclusion/root/publication proof. Scalar session/handle labels cannot issue any of these guards. The current key includes the actual stop/runtime epoch and every participant's actual module/function/offset/epoch/function generation.

An extension returns a new path handle and retires its predecessor after the complete new path has actually been traversed. Continue, new stop, replacement and domain close clear the ledger; counters never reset or wrap. Maximums are4096 original edges,128 live handles and32768 integer indices (256KiB path DATA) per controller session. DAP stores only original path anchors, has its own32768-index budget, and reuses the backend's scalar DATA labels under the complete current stop key. Each read still traverses the full original path anew. No arbitrary host memory or dense reply object ID is an input.

The private reader retains only root+current scratch metadata while walking a long path under the actual lexical N exclusion; after64 terminal members at most66 query-local objects exist. Original fixed16-edge requests preserve their current format and shallow scratch population. Deep replies echo `@SESSION:HANDLE depth=DEPTH` instead of printing thousands of indices, and bind path protocol1 to typed view3. Original and terminal aliases/cycles remain valid. Cold query allocations/lookup never occur in ordinary non-debug generated IR or memory access.

`debug_wasm_path_data.cc` and `test_dap_deep_wasm_path.py` test finite grammar/quota/retirement DATA only. `debug_gc_deep_paths_runtime.cc` uses the actual modern4097-node Wasm rooted chain, existing real two-participant owner producer and fresh typed native reader at depths64/1024/4095/4096, plus4096-edge cycles, extra-reader exclusion, incomplete cohorts and4097 rejection. It uses synthetic echo labels only; these cannot substitute for actual captured native owners. It does not qualify controller/UI ledger integration or VM restoration by itself.

No native compilation/execution, official WAT validation or CLI/DAP integration execution was done while constructing this private packet. Run those through the Linux64GiB keeper for both products/instruction and unwind, then QEMU endian coverage. The path quota is explicit; this is finite deep traversal, not unbounded graph recursion.

The original field/element path follows Core3 structure/array store values and exact declared reference/packed field types. [Core3 types](https://webassembly.github.io/spec/core/syntax/types.html) and [runtime store structures](https://webassembly.github.io/spec/core/exec/runtime.html) keep reference representations opaque. This debugger preserves that boundary by reporting logical identities/typed members and never raw reference representation/native addresses.
