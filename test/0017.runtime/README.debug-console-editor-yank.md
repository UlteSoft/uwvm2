# HOST command kill/yank and VT Home/End — PRIVATE SOURCE

Source-only, no compilation/native/live acceptance. GDB uses Readline; its [killing commands](https://www.sourceware.org/gdb/current/onlinedocs/gdb.html/Readline-Killing-Commands.html) and [command bindings](https://www.gnu.org/s/bash/manual/html_node/Commands-For-Killing.html) describe saved kill text, adjacent kill coalescing, CtrlY insertion, and MetaY cycling immediately after yank. This is a bounded independent implementation, not an unbounded external Readline dependency.

The existing HOST editor now owns eight 512-byte kill items. CtrlK saves suffix, CtrlU saves prefix and CtrlW saves previous whitespace-delimited word; adjacent kills combine in natural byte order. CtrlY inserts the complete newest item only if it fits. ESC y cycles the actual immediately preceding yank; movement/insertion/history/search breaks replacement eligibility. Overflow checks occur before line deletion/insertion; rejected yank/pop leaves the actual line/cursor intact. Deleting/backspacing alone never replaces killed text. The ring survives input begin but executes nothing automatically; CtrlC discards current input/repetition and never implicitly executes ring contents. New total fixed storage is 4096 bytes per editor, no heap, I/O, symbols, guest/native memory, controller permissions or hot guest path.

The same bounded escape decoder additionally accepts common VT Home 1~/7~ and End 4~/8~, retaining existing H/F/3~ behavior and whole-command rejection of unknown/incomplete escapes. The editor's ESC-y input is source-qualified only; Windows native Alt-modifier conversion requires its separate provider qualification, while CtrlY follows its ordinary control-character input. No signal, WASIp1 syscall, native stepping or provider file has changed. Existing header-wide exported namespace already exports the new maximum_kills constant and class members via console_line_editor.cppm; no new production header needs import/export.

The paired actual HOST unit contains empty-ring, point insertion, forward/backward adjacent kills, UTF8 whitespace word erase, same/ring ordering, eight-item eviction/rotation, interruption, exact capacity, overflow rejection, yank replacement invalidation, and VT HomeEnd/Delete/unknown escape oracles. It supports a named-module TU variant without a fast_io.h preimport. It must run alongside the prior editor/shortcuts and real keyboard/PTY/FIFO components under the original Linux keeper, then actual product PTY CtrlY/terminal display checks. These tests do not manufacture VM-stop or shutdown ACK and do not claim full GDB, all input devices, all platforms, or performance qualification.
