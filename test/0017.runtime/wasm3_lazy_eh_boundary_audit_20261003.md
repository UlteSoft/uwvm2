# Core 3 lazy EH boundary scan correction — source candidate

The ordinary LLVM lazy callee-discovery grammar did not recognize `throw` (0x08) or `try_table` (0x1f), although pure validation and full interpreter/LLVM walkers already implement these Core 3 instructions. Callee collection consequently returned false and stopped discovering calls in such bodies. This is a source-confirmed metadata omission; no native module refusal or performance improvement is asserted.

The correction uses the existing bounded u32, blocktype and wasm3 catch-vector decoders. The outer instruction cursor remains at its opcode on every failure, even if a local temporary decoded a valid blocktype before a malformed catch vector. Only the complete immediate commits it. Feature/tag/outer-label/operand checks remain in the original fused validation/emission pass. There is no whole-body prevalidation, new feature flag or runtime EH change. ROS intentionally has no lazy backend and receives only the shared new syntax fixtures/runner cases.

`llvm_jit_lazy_core3_exception_scanner.cc` checks 26 grammar/boundary outcomes, including four literal catch kinds, padded u32 indices, exnref blocktype, throw_ref and direct calls after EH immediates; truncated/overflow/unknown-kind failures must preserve the outer cursor. Its empty module is explicitly only a grammar carrier. It cannot prove initialized-module authority or Wasm validity. The older raw scanner test is adapted to the current module-argument API; its former call signature would not compile against current headers.

Four complete WAT fixtures use real cross-function throw/catch and a later direct call returning47, reached from `_start`. Names in the existing five-entry decision comparison runner: `lazy-eh-scan-catch`, `lazy-eh-scan-catch-ref`, `lazy-eh-scan-catch-all`, `lazy-eh-scan-catch-all-ref`. Each requires official assembly/validation on the same bytes, then pure validation, int full/lazy and LLVM full/lazy (plus optional lazy+verification); ROS runs pure/int-full/LLVM-full. Compile the ordinary grammar component against the freshly aligned current source/runtime and LLVM SDK in the existing Linux64GiB cgroup. No local/native test was performed.

Specification: [Core 3 binary instructions](https://webassembly.github.io/spec/core/binary/instructions.html), [Core 3 validation instructions](https://webassembly.github.io/spec/core/valid/instructions.html). This focused correction does not establish all-opcode equivalence of the independently adapted stacks/control walkers.
