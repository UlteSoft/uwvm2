# Candidate single-traversal lazy admission design

This is a review-only design based on current source. It is not implemented,
included, benchmarked, or qualification evidence. Existing lazy admission must
remain intact until the replacement can prove every body, including unused ones.

Current source evidence (ordinary product; ROS exposes full modes only):

1. `uwvm/run/run.h:2435` calls `runtime::validator::validate_all_wasm_code()` before
   any lazy execution, then `cfg.assume_full_code_verified=true` at 2446. This is
   the real successful CLI path; `-m validation` at 2070 is a separate valid API.
2. `runtime/lib/uwvm_runtime.h:481` carries that scalar in public lazy config.
   `uwvm_runtime.default.cpp:16322` selects the int lazy validation mode and 16337
   stores it in options; 16712 and 16753 do the same for LLVM. The mode also enters
   runtime state signatures. It is not an owned semantic proof.
3. Int `compile_cu_from_lazy_validator/translate.h:163-250` stores raw borrowed
   `code_begin/code_end`, unit indices and scheduler state. `function_only` at
   1965 returns after metadata construction, with no operand/control validation.
   The default structured scanner reads immediates and boundaries, not the full
   type/local-init semantics. There is no checked opcode IR in that representation.
4. Demand scheduling at `uwvm_runtime.default.cpp:9825-9834` passes those options
   to the actual request. Int lazy 2209 calls the full fused local-function
   compiler. LLVM lazy 2488/2570 does the same. Both full compiler traversals
   perform authoritative semantic checks while emitting their backend product.
5. LLVM metadata at lazy `translate.h:284-292` also stores raw Wasm spans.
   The call-graph scanner at 1237/1518 independently decodes raw immediates.
   `lazy_validation_mode` is presently read for labels/logs, not an alternate
   semantic-plan consuming code path. The `assume` flag does not remove the
   repeated full fused checker.
6. Full production translation calls the fused local-function compiler directly.
   LLVM `single_func.h:2163` enters `validate_runtime_local_func` while emitting;
   int lazy 2209 enters the equivalent full compiler. LLVM helper 2394 is a
   public validation-only entry; 2906 deliberately emits nothing for a partial
   private pending-numeric-plan request. These are not successful normal full
   prevalidation passes and must not be conflated with item 1.

The existing first validator plus later fused decoder is therefore redundant
work for a called lazy function. Deleting the first validator alone would allow
an uncalled invalid Core3 function to survive admission and permits start effects
before its validity is known. The three invalid files in `lazy/` preserve that
required module-level behavior. Core3 requires all module components and every
function expression to be valid, irrespective of whether execution reaches them.

The narrowest correct replacement is a sealed owned function plan generated by
the SAME authoritative decode/type-check traversal during lazy admission. It
must be a translated representation, not a flag beside raw bytes. The backend
materializer accepts only that plan and never invokes a Wasm decoder or a Wasm
semantic validator. This makes admission validation plus translation one pass;
only backend lowering/native code generation remains deferred.

A concrete staged representation:

- A module plan owns a source/initialized-module lifetime pin, immutable type
  context/canonical-ID owner, module identity and generation, code grammar/version,
  and a collection of independently owned function plans. Publication succeeds
  only after all local function plans seal; no start or host entry is invoked
  while any body is incomplete. Errors discard all private plans.
- Each function plan contains compact typed opcode records, source byte offsets
  and widths, checked decoded immediates, fixed type/ABI carrier IDs, actual
  control/branch label IDs and edge argument shapes, local layouts and precise
  root/exception/debug metadata. Variable immediates use module-wide owned pools
  with checked `[first,count]` indices. The plan stores exact heap/nullability and
  subtype witnesses; a funcref carrier must not erase a GC or exception heap.
- Distinguish nonexecuting polymorphic/dead instructions from live operators.
  Their syntax and stack/local-init constraints are still validated once. Record
  debug/error offsets without inventing live operands from Bot. Record explicit
  try_table outer target labels/tag payloads and deterministic unwind scopes.
- Every memarg is represented by checked scalar alignment, memory index, unsigned
  64-bit offset and memory address type; table/memory cross-copy length types and
  atomics' shared-memory/alignment checks are already proved. SIMD lanes, relaxed
  SIMD descriptors, packed-field choice, ref-cast nullability, return-call ABI,
  catch-ref hierarchy and recursive type identities must survive unchanged.
- Produce execution-unit boundaries, direct callees and indirect-target witnesses
  during this traversal. That replaces the int raw structural scanner and LLVM
  raw call-group scanner instead of adding a third pass. Record function feature
  requirements with their first source offset/subject; parser module declaration
  aggregates handle unused types and count-zero locals without body rescans.

Integration sequence that preserves existing full modes:

1. Add an optional plan sink to shared semantic helpers and each CURRENT fused
   compiler branch. The branch decodes once, calls its existing shared semantic
   helper once, and appends the normalized checked operation after success.
   Full emitters continue directly from the same checked effect. A plan-only sink
   during lazy admission omits backend code emission but TRANSLATES into records;
   it cannot delegate to a pure validator followed by a separate decoder.
2. Introduce a private builder and a sealed read-only handle. The seal requires
   balanced controls, complete function end at the exact owned byte bound, result
   compatibility, scoped local initialization and all type/declaration gates.
   No public caller or guest can construct the seal by setting a bool.
3. Module readiness requires a sealed plan for every defined body. Replace the
   CLI validator call with that single fused prepare transaction. Remove both
   `assume_full_code_verified` variants only after every entry, tiered fallback,
   background request and embedding API consumes actual plan ownership.
4. Int materialization replays checked operations into register-ring/conbine
   codegen; it does not rebuild a validation operand/local-init stack or reread
   LEBs. Delayed combinations use normalized record boundaries and exact types.
   LLVM materialization creates SSA/LLVM IR from the same records, or stores
   already emitted private per-function LLVM IR during admission and only defers
   optimization/MCJIT. The latter is a smaller interim implementation, but its
   retained IR/startup memory must be benchmarked and must not be called zero-cost.
5. Tiered T0/LLVM, fallback, prefetch and unwind groups share the same plan IDs and
   sealed type/call metadata. Native lowering failure cannot trigger a raw-Wasm
   revalidation fallback; use another backend lowering of the same checked plan.

Lifetime and pointer safety:

Use owned vectors/pools and indices. Test `index < size` before each record read;
test `first <= size` and `count <= size-first` before any pool view. Resolve source
positions only on diagnostic/debug paths after `offset <= body_size` and a live
source pin, allowing one-past solely as a borrow. Preserve before/after cursor
comments in the one initial bounded decoder and every cold diagnostic pointer
assignment. Materialization never moves a raw Wasm pointer. Policy/type/source
or hot-replacement generation changes retire the handle and invalidate waiters;
late publication is forbidden. Reset stops workers and drains all plan leases
before releasing source/module ownership, following current runtime barriers.

A proof cannot be reused across a different code grammar merely because binary
format version is 1. Core3 u64 memargs and legacy immediate grammars must be
separate immutable plan attributes. A stricter feature subset can consume a plan
only after its exact module/body requirement summaries admit it; changing grammar
or actual initialized type identity requires a new complete admission transaction.

Performance validation after implementation:

For the seven lazy fixtures, official oracle validation is first. Invalid unused
bodies must fail before `_start` side effects in pure, int full/lazy and LLVM
full/lazy. Valid Core3 probes must actually execute. Add cold test-only counters
at the single source decoder and semantic helper, observing each admitted opcode
once and zero new raw reads/checks at demand/prefetch materialization; flags/log
labels alone are not evidence. On SSH Linux P-core compare time to first entry,
peak cgroup memory, normalized plan bytes/op, full/startup latency and hot memory
access assembly against current full and lazy paths. Test every conbine/delay
setting and EH instruction/unwind policy. No per-memory-access proof guard is
added: existing safe memory lowering stays unchanged.
