# Parser-owned checks before initialization effects (source candidate)

This private source factory reads the actual file into one exclusively owned immutable image BEFORE selecting/loading/parsing a fresh source. SHA-256, the parser, code/type/segment spans, the complete Core3 function validator and the eventual initializer use that SAME image. There is no mutable mmap or postparse source copy in this staged path. It retains the original full feature policy/type closure and does not call module construction/provider initialization, initialize_runtime, global/table expression evaluation, segment application or start execution before every unused function has passed. Only a const canonical source owner is published; the factory's mutable owner remains private. All native configuration/file selection/reset remains serialized and drained. After the seal no native caller may reload/mutate the selected file, parsed metadata or loader configuration until drained retirement; existing internal global native borrows are readonly initializer inputs. Multi-file, preloaded/provider/weak-symbol configurations are explicitly outside this first private factory rather than silently initialized before the body checks. This is owned compiler DATA, not execution admission or a generation lease.

The ordered source identity contains complete actual source SHA-256/length, ordinal 0, real binfmt version and parsed import/function counts. Any import leaves the provider source closure explicitly incomplete. Source identity never claims effective replacement bodies, exact build/provider/toolchain/ABI identity, generated cache entries, guest isolation or checkpoint/restore authorization. A path, version macro or the JIT function-only cache fingerprint cannot substitute for full source bytes. Metadata agreement during the file read does not prove an atomic filesystem version; the immutable result identifies precisely the actual bytes which were parsed.

`parsed_source_image_status` separates actual file-provider/open/read/quota/allocation failures from Wasm validation. The factory returns no owner and leaves the supplied `code_validation_error` unchanged when image creation is unavailable; it never classifies a legal over-limit input as invalid Wasm and never falls back to a mutable mapped source. The original CLI mapper remains available and unchanged. Source/image and retained-record budgets are separate compiler resources, not validity rules or whole-process RSS limits.

The Ordinary binder accepts this private parsed-plan owner, verifies the real initialized registry/module/function/code/signature/generation and copies the SAME function record owners. It has no body decoder, LEB scanner or type-validation replay. Existing default CLI lazy/full/tiered routes remain unchanged. Multi-file/host-provider setup, every physical lowering, register-ring lowering and LLVM retained consumers are pending; this candidate does not claim that the entire default instantiation pipeline has been replaced. Reset races and concurrent source-file mutation are unqualified.

The native fixture must run the invalid unused non-null GC local FIRST. Although earlier GC code and extended-constant global/table initializers are valid, the actual source registry and global active runtime registry must remain empty, no module map is constructed, and the real initializer serial must stay unchanged. It then requests an actual image limit of 1 byte: image creation must be resource-unavailable with validation error still OK, no source selected and no generation/serial/registry mutation. The valid source must first mint a checked plan while the same invariants hold. With the runner's mandatory fourth SHA argument, the fixture verifies full identity against the original oracle file, overwrites only a dedicated mutable file copy through fast_io native RAII and then uses the original immutable bytes for the real loader/linker/initializer, global 42, table ref.func and result 47. Original oracle artifacts must remain pinned/intact while the deliberately overwritten probe changes hash. It finally denies the old plan after genuine reset/retire with a real weak-owner expiry. This proves a specific sequential overwrite/lifetime case only when actually executed, not concurrent filesystem versioning or concurrent reset.

Ordinary additionally compiles `parsed_before_init.cc` with `-DUWVM_TEST_ORD_CHECKED_LAZY_CONSUMER=1`: both actual byref and musttail-no-cache record consumers are mandatory, startup streams are empty, only requested function 1 materializes, its actual result is 47, and valid GC function 2 is explicitly unsupported without raw fallback. ROS omits that flag and qualifies the shared parsed-before-effects component only; ROS has no lazy mode. Do not call the ROS component a lazy execution test.

Use exception-enabled builds for this catch-observing component. No-exception header/module qualification and invalid-input death tests are a separate future component. `run_parsed_before_init.py` is restricted to the sole SSH Linux keeper inside the existing <=64GiB/no-swap cgroup. Its self-check requires this live Python PID in the exact visible cgroup leaf (including namespace/mount-root mapping), the verified 0,2,4,6,16-31 effective CPU set and bounded affinity. An ancestor memory limit, an environment variable or a nonempty build record cannot admit execution. The external reviewed keeper guardian must still bind EVERY oracle/native child PIDFD, actual membership, literal argv, limits, timeout/reap and exact source/object/executable before/after closure. The runner's self observation explicitly records `guardian_qualification=false`; it is not a substitute for those receipts. Official wasm-tools must parse and validate both original WATs; the bad module must be rejected specifically for the unset non-null local. The new input includes GC, memory64, table64, extended const and explicit table initialization.

A nonempty `--build-record` only identifies the evidence file; it does NOT establish freshness. The keeper must verify exact candidate before/after hashes and real runtime/support/own-main objects and executable artifact bindings. The Ordinary lazy storage/checked-plan ABI changed: fresh ALL THREE production TUs/BMIs and same-layout support are required, then link a fresh own-main instead of the product main object. Old R8/R9/R4 integer objects cannot qualify these source changes. No local native build or execution, oracle, assembly or performance result has been produced for this candidate.

Module closure qualification (independent from runtime execution): freshly precompile every transitive public provider/module from this exact candidate, including fast_io_crypto (the real SHA-256 provider), utils.control (owned image), retained_plan -> wasm3:validator -> wasm3 aggregate and checked_source. Precompile parsed_checked_module_capsule.cppm, compile parsed_checked_module_consumer.cc with its new PCM, link the capsule object and only required actual provider objects, then execute the focused DATA component in the same bounded SSH Linux cgroup. It loads no file and does not qualify the before-effects runtime fixture or physical lowerer. Missing aggregate export must be a compile failure, never resolved by including retained_plan.h in the importer. Header and import consumer qualifications must be recorded separately.

The normative order is based on Core 3 [module validation](https://webassembly.github.io/spec/core/valid/modules.html#modules), which requires every component to validate, and [instantiation](https://webassembly.github.io/spec/core/exec/modules.html#instantiation), which performs initialization only for a valid module. The staged integer DATA representation and later lowering are an incomplete experimental lazy slice, not completion of the four requested fused validation/translation paths.
