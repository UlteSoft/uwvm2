# First real synchronous INT/LLVM i32 compiler slice

This SOURCE proposal starts the requested one-typing-walk architecture. The original INT single-function fused walker is the sole byte decoder and abstract-type transition issuer. It still builds its original register-ring stream, consumes its terminal `end`, checks the exact result stack, performs its original pointer fixups and moves the actual compiled stream into its owner. Synchronously, the optional compiler sink consumes already accepted `i32.const`, `local.get`, and all eighteen primary i32 numeric events through the existing real LLVM physical SSA helpers. LLVM module/function verification is mandatory before retaining a native-IR fragment. The factory seals only after ALL local functions have passed the original walker, including unused functions.

The new sink takes no raw instruction pointer or slice. It can borrow finalized runtime type/code metadata for source identity and function ABI, but never decodes that body. It requires contiguous first-issued event extents from expression start through terminal `end`; original combine skips, lookahead elision or replay decline that optional IR fragment. Unsupported but legal instructions, polymorphic/nested control, non-i32 signatures and resource quotas decline LLVM availability while the original ring still validates and emits the whole function. No pure validator prepass, LLVM validator walk, raw call-body matcher, runtime READY state, native address issuer or saved-state permission is added.

This first slice is explicitly partial: straight-line i32 functions can produce both real physical artifacts. Modern memory64 module declarations and an unsupported legal i31 function are included in the positive fixture. This does not yet cover all Core3 instructions, wire the dual artifact into lazy/tiered startup, or close whole-tiered single typing. Existing lazy/T2 parents still have their admitted INT and LLVM walks; removal of T2 replay is not evidence that those two walks became one. The selected research factory leaves `trivial_kind=none` rather than reread raw bodies; automatic tiered wiring must first replace that optimization with event-derived checked metadata, preserve all call/ABI/root/fixup policies, and measure cold latency/memory and execution cost. No performance result is claimed here.

Default INT compiler instantiations use the empty discard transaction and all new hooks are under `if constexpr`; no LLVM IR or guest instruction is emitted by the default path. The original ring ABI, opfunc/musttail functions, memory guards, and LLVM numeric expressions are unchanged. Compilation counters/quotas are cold only. The policy bounds optional retained function count, emitted operation count, per-function operations and local count. It is not a total RSS/LLVM allocator quota or a guarantee that the existing allocator can recover from OOM. RAII drops SSA/state before its module/context on rejection and unfinished validation.

## Actual tests to run only in the Linux keeper's 64 GiB cgroup

`finite_tests.py --wasm-tools ACTUAL_PINNED_TOOL --component ACTUAL_FRESH_COMPONENT --source-dir THIS_DIR --work-dir NEW_CG_OUTPUT` is bounded to three official parses, one valid oracle, two specific invalid-code oracles and one real component execution. The same recipe applies independently to both products. Every compiler variant uses matching fresh runtime/host objects, actual LLVM/provider closure, selected before/after source identity and dependency MD; do not overlay a historical ELF or assume the module capsule compiles. Build `real_i32_dual_sink.cc` with both compiler implementations enabled and without `UWVM2TEST_RUNNER_USE_LLVM_JIT` or `UWVM2TEST_STRICT_NO_INTERPRETER`. Link the existing complete real provider closure; no fake host bridge definitions. A second variant defines `UWVM2TEST_DUAL_I32_TAIL` and executes actual original musttail ring functions.

`finite_build_variants.json` enumerates all 32 combinations of four supported cumulative combine levels, soft/heavy delay bits, and by-reference/musttail interpretation. The first minimal two cells should resolve API/ABI failures before expanding the matrix. Mandatory checks include exact 18 numeric edge results in BOTH original ring and actual MCJIT modules, real local parameter/default initialization, modern unsupported i31/nop/skipped-constant ring execution, moved-from owner and zero quotas, and precise unused modern memory64/i31 body diagnostics. The negative official oracle requires a real `(at offset 0x...)` code diagnostic and rejects CLI/feature/I/O failures and signal exits. Product-level startup/side-effect admission, recursive/typed-ref/tail/EH dual sink, trap delivery, raw ABI/CFI publication and actual P0 performance remain separate future tests.

Compile the real `module_capsule.cppm` after actual required modules and link a consumer in a fresh namespace to prove module name/type ownership and optional template reachability. A source import graph without a cycle is not a BMI qualification. Inspect default versus selected INT generated code and LLVM IR only after real compilation; byte-equal source expressions alone do not prove machine-code equivalence.

## Authoritative rules used

The Core3 [numeric typing rules](https://webassembly.github.io/spec/core/valid/instructions.html#numeric-instructions), [variable typing rules](https://webassembly.github.io/spec/core/valid/instructions.html#variable-instructions), [integer execution rules](https://webassembly.github.io/spec/core/exec/numerics.html#integer-operations), and [function validation](https://webassembly.github.io/spec/core/valid/modules.html#functions) define the first transition and numeric behavior. The existing shared `i32_numeric_event`/typed-stack kernel performs that transition; this proposal does not create another eighteen-opcode type checker. Physical LLVM lowering reuses the original normalized emitter, including zero-defined clz/ctz, wraparound, masked shifts, divide-by-zero and signed-overflow traps, and min/-1 remainder handling.
