# Error-returning fast_io control filesystem operations

This source candidate adds one implementation shared by C++ EH and no-EH builds. Native execution is pending. The independent vendor directories in both products contain byte-identical changes; the sibling fast_io checkout is untouched. The ordinary-tree patch is `ordinary-fast-io-posix-nothrow.patch` in this candidate's source packet.

The public Linux/Darwin APIs are included by `fast_io.h` and exported by the fast_io named module:

* `posix_status_nothrow(observer)` and `posix_fstatat_nothrow(at_entry, validated_nul_path, raw_at_flags=0)` return `{posix_file_status value, int error}`. A failed result contains zero-initialized metadata, not partially written native data.
* `posix_openat_nothrow(at_entry, validated_nul_path, raw_native_flags, perms)` returns a move-only `{posix_file file, int error}`. The API does not add `O_CREAT`, `O_TRUNC`, `O_CLOEXEC` or convert an `open_mode`; caller-supplied native flags are passed unchanged. The successful result owns the descriptor immediately.
* `posix_truncate_nothrow(observer, uintfpos_t size)` and `posix_close_nothrow(posix_file&)` return `{int error}`. Oversized truncation returns EINVAL. Closing releases the owner before one actual close and never retries EINTR or closes it twice.
* `posix_read_nothrow(observer, writable_byte_buffer, byte_count)` returns `{size_t transferred, int error}`. Successful zero is EOF; native EINTR remains caller policy. The buffer is borrowed only during the synchronous call. This is a host file operation and grants no debugger address authority.

* `posix_write_nothrow(observer, readable_byte_buffer, byte_count)` returns the same byte-transfer layout through `posix_write_result`. It issues one native write and returns partial transfers/EINTR without retry, allocation, locks or flush. Linux uses the existing fast_io raw syscall primitive without changing errno; Darwin uses the SDK cancellation-aware asm/noexcept alias. A signal-handler caller retains its own errno/save/restore policy and must not add ownership/formatting/flush operations in the handler.

* `posix_fsync_nothrow(observer)` returns `{int error}` for one actual file/directory fsync, without retry or ownership change. A buffered caller must flush its fast_io buffer first. Linux uses the existing raw syscall and Darwin the actual SDK asm/noexcept alias. Native errors such as EBADF, EINVAL and EINTR remain explicit caller policy. This is not fdatasync and does not issue Darwin F_FULLFSYNC; accepting a request does not qualify a filesystem's power-loss durability or publish/flush its parent directory automatically.

Zero error means success; native failure errno is copied before any file retirement can change it. POSIX open results are uniquely owned, not copyable. No operation calls throw_posix_error or uses separate EH/no-EH parsing. glibc aliases follow the native struct-stat/off-t `_FILE_OFFSET_BITS` and time64 redirects; optional stat64 declarations alone do not select layout. Darwin uses the SDK's inode64 and cancellation symbol macros and preserves the old-system AT_FDCWD-only fallback. musl's `_REDIR_TIME64` is handled separately from glibc; Bionic's file-offset redirect affects ftruncate. Actual cross-ABI qualification is still required; source branches are not architecture PASS evidence.

Sealed input uses these status/at/truncate results for regular, special, socket and pipe identity comparisons. Raw `O_TRUNC` is removed before opening, the unpublished RAII owner pins the exact checked object, and truncation occurs only after authorization. ioctl/PTY/pipe identity, duplicate-CLOEXEC, peer credentials and other control-specific syscalls remain their existing asm-noexcept operations. Authentication and failure decisions are unchanged.

The new `posix_nothrow_files.cc` performs real error-return, missing-file/no-implicit-create, no-implicit-truncate, descriptor mode/CLOEXEC, full metadata identity, byte read/EOF, zero/error/real nonblocking partial write, actual file/directory fsync plus invalid/pipe errors, invalid/second close, oversized truncate and sealed alias/deferred truncate checks. The existing kernel credentials, PTY, pipe, hardlink/symlink, concurrent-denial and module-consumer tests remain required. Run `run_session.py` only in the sole keeper's SSH Linux 64 GiB cgroup; it now builds this unit under O3, ASan+UBSan/leaks and no-EH and exercises its public operations from a real module import. The filesystem unit uses tmpfs for operation/error semantics; it is not a persistent-volume or power-loss test. No local native test was run.

Primary ABI declarations: [glibc stat](https://raw.githubusercontent.com/bminor/glibc/master/io/sys/stat.h), [glibc fcntl](https://raw.githubusercontent.com/bminor/glibc/master/io/fcntl.h), [glibc unistd](https://raw.githubusercontent.com/bminor/glibc/master/posix/unistd.h), [Bionic stat](https://raw.githubusercontent.com/aosp-mirror/platform_bionic/master/libc/include/sys/stat.h), and the actual Apple SDK `sys/stat.h`, `sys/fcntl.h`, `unistd.h`, `sys/cdefs.h`. The musl primary cgit endpoint was unavailable during source review; its branch remains pending actual header/ABI qualification and is not claimed tested.

* `posix_seek_nothrow(observer, intfpos_t offset, seekdir)` returns `{intfpos_t position, int error}`. It accepts only beg/cur/end and calls the SDK-selected native `lseek` once; native seek ABI range overflow is EOVERFLOW and native EINTR is returned without retry. It neither closes nor owns the descriptor. glibc uses its SDK __off64_t/lseek64 and Bionic off64_t/lseek64 regardless of FOB64, preserving existing Linux32 large-position support; musl uses native off_t64/lseek, and Darwin uses its unaliased _lseek symbol. When no native wide seek ABI is selected and the target headers advertise __NR_llseek, r11 uses the existing fast_io raw-syscall provider with the documented Linux kernel five-argument split-offset ABI. No guessed libc lseek64 symbol is used. The new Linux-only `posix_nothrow_seek.cc` cross-checks actual positions with independent SDK lseek, >4GiB sparse seek including a known glibc/Bionic native off_t32 build, invalid directions/negative positions, pipe ESPIPE and closed EBADF. Darwin and Linux32 runs remain unqualified until the keeper executes them.

Revision r10 corrects the source-only r9 Linux32 narrowing risk. It uses the genuine libc large-file seek type/symbol, so the public 64-bit position contract is preserved without duplicating split-offset kernel ABI code. The r9 freeze is retained and has no native qualification.

Revision r11 preserves the existing >2GiB contract for remaining native off_t32 Linux providers using __NR_llseek (high32/low32 plus an owned 8-byte signed result). Known glibc/Bionic wide libc and musl/Darwin native64 branches stay unchanged. Unknown libc independent stat/oracle qualification is still pending; this source branch is not a platform PASS. Primary kernel declarations: [Linux llseek](https://github.com/torvalds/linux/blob/v6.17/fs/read_write.c), [target syscall selection](https://github.com/torvalds/linux/blob/v6.17/include/uapi/asm-generic/unistd.h).

Revision r12 also accepts the real __NR__llseek spelling used by i386/ARM headers; generic/RV32 uses __NR_llseek. If both are declared they must have the same numeric value. The public operation selects a target-provided constant without creating a compatibility macro or assuming a syscall number. Known wide libc branches are unchanged; i386/ARM execution and independent SDK oracle qualification remain pending. [i386 kernel syscall table](https://github.com/torvalds/linux/blob/v6.17/arch/x86/entry/syscalls/syscall_32.tbl), [ARM kernel syscall table](https://github.com/torvalds/linux/blob/v6.17/arch/arm/tools/syscall.tbl).

`posix_getfl_nothrow(observer)` returns `{int flags, int error}` for one readonly F_GETFL. Flags zero is success, and errors such as EBADF/EINTR remain explicit caller policy. Linux uses its declared fcntl/fcntl64 syscall scalar ABI; Darwin uses the SDK cancellation-aware __DARWIN_ALIAS_C(fcntl) declaration. The public API exposes no arbitrary command, lock structure, pointer or mutation. Its named-module exports share the same EH/no-EH implementation. The Linux memfd/pipe unit cross-checks real SDK fcntl, native NONBLOCK/APPEND changes and retired descriptors. Actual O3/noEH/Linux32/Darwin qualification is pending. Primary declarations: [glibc](https://raw.githubusercontent.com/bminor/glibc/release/2.42/master/io/fcntl.h), [Bionic](https://raw.githubusercontent.com/aosp-mirror/platform_bionic/master/libc/include/bits/fcntl.h), installed Apple SDK sys/fcntl.h605.
