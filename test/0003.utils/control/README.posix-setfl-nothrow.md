# Dedicated error-returning F_SETFL operation

This is an API 11 source proposal on top of the live API 10 getter. The proposed vendor header and named-module export are in the separate review packet; they have not been applied to the live vendor trees. The two new test sources are byte-identical in the ordinary and ROS products. No local native compilation or execution was performed. Native qualification is pending.

`fast_io::posix_setfl_nothrow(observer, int native_flags)` returns the existing `posix_operation_result { int error; }`. A zero error is native success. It issues exactly one `F_SETFL` with the supplied integer unchanged. It accepts no caller-selected fcntl operation, pointer payload or file-lock structure. It does not allocate, throw, retry, alter descriptor ownership, convert an `open_mode`, mask requested bits, read flags back or roll them back. The caller retains the file owner and serializes any read/modify/set/verify/rollback sequence. Duplicated descriptors can share the same open file description, so the primitive cannot make that larger sequence atomic.

Linux uses the actual target header's `__NR_fcntl`, otherwise its `__NR_fcntl64`, through the existing fast_io raw-syscall provider. The scalar `F_SETFL` payload does not use the distinct file-lock layout. Native negative errors are returned explicitly, and the raw syscall does not change libc errno. The libc fallback uses a dedicated noexcept asm declaration selected by the SDK: glibc time64 `__fcntl_time64`, file-offset64 `fcntl64`, or the native `fcntl`; Darwin uses its declared `__DARWIN_ALIAS_C(fcntl)`. No syscall number, flag value, libc ABI structure or symbol suffix is guessed. BSD/Cygwin branches are not exposed or qualified by this addition; consumers preserve their existing fallback branches.

Native success does not mean every requested bit took effect. On Linux `F_SETFL` ignores access modes and creation flags, and attempts to change `O_SYNC`/`O_DSYNC` can return success while leaving those bits unchanged. WASI consumers must preserve their existing verification and rollback decisions, including their individual error mappings. This API does not strengthen synchronization or implement an implicit transaction.

`posix_nothrow_setfl.cc` uses real Linux memfd and pipe objects with RAII owners. Its independent oracle binds to the public SDK-selected libc symbols, separately from the production raw syscall. It covers invalid and retired descriptors with actual EBADF, errno preservation by the raw operation, append/nonblocking enable and clear, access mode and CLOEXEC preservation, an ignored creation/truncate request with real file size and position checks, actual empty-pipe EAGAIN, and native ignored-SYNC success followed by caller verification and rollback. Only errors actually produced by these objects are qualified; append-only EPERM, cancellation/EINTR, other libc ABIs and injected consumer failures remain separate tests. The new named-module consumer calls both get/set APIs through a freshly produced PCM and checks their exported result types and actual invalid-descriptor errors.

The sole SSH Linux keeper must run both tests from the same frozen source/provider closure in the shared 64 GiB cgroup, in EH and `-fno-exceptions` profiles. Produce a fresh fast_io PCM and object separately for each profile; do not reuse stale module artifacts or force-include headers into the import-only consumer. Retain compiler dependency output, actual executable/provider identity, raw output and original-supervisor retirement records. ASan/UBSan may be added when the ordinary EH/noEH checks pass. A source branch or module export is not a platform PASS.

Primary references: [Linux F_GETFL/F_SETFL](https://man7.org/linux/man-pages/man2/F_GETFL.2const.html), [POSIX fcntl](https://pubs.opengroup.org/onlinepubs/9799919799/functions/fcntl.html), and [glibc's public fcntl declarations](https://raw.githubusercontent.com/bminor/glibc/master/io/fcntl.h). The POSIX 2024 and 2017 function pages returned HTTP 403 during this review, so their contents are not claimed read; the indexed extract of Open Group [fcntl.h definitions](https://pubs.opengroup.org/onlinepubs/007904875/basedefs/fcntl.h.html), Linux's current manual and [Linux 6.17's setfl implementation](https://raw.githubusercontent.com/torvalds/linux/v6.17/fs/fcntl.c) were checked. The local MacOSX26.4 SDK `sys/fcntl.h:605` and `sys/cdefs.h:791` were inspected read-only for Darwin's exact signature and alias. This is declaration review, not a macOS runtime qualification.
