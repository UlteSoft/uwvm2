# Linux fdatasync error-returning API candidate

API 12 is a source-only proposal on top of the live API 11 header/module. The vendor changes remain in the separate review packet and have not been applied. The new tests and this document are identical in both products. No local compilation or native execution was performed.

`fast_io::posix_fdatasync_nothrow(observer)` returns the existing `posix_operation_result { int error; }`. It accepts one borrowed, caller-pinned descriptor and issues one actual Linux `fdatasync`, with zero error for native success. It has no allocation, throwing path, buffer flushing, descriptor ownership transfer, retry, implicit fsync or error remapping. In particular, native ENOSYS remains ENOSYS. The existing WASI caller decides whether to invoke its separate `posix_fsync_nothrow` fallback and preserves its current error mappings.

The function and named-module export are guarded by `__linux__`; this candidate does not add a Darwin, BSD, Cygwin or Windows API. Where the actual target headers define `__NR_fdatasync`, the existing fast_io raw syscall provider is used and returns its native error without modifying libc errno. The Linux libc fallback has the SDK's `int(int)` signature and a dedicated noexcept asm link to `fdatasync`. Its scalar descriptor ABI has no file-offset64/time64 payload or symbol redirect. This declaration was checked against glibc's public header and Linux implementation; other Linux libc/architecture combinations and the fallback branch still require actual provider qualification.

Callers flush any user-space output buffer before requesting data synchronization. This API does not replace metadata synchronization, `fsync` of a parent directory, or fast_io's other synchronization operations. A tmpfs success test qualifies operation/error behavior only; it is not evidence of durable storage or recovery after power loss.

`posix_nothrow_fdatasync.cc` uses actual memfd and pipe objects. An independent SDK-linked libc oracle checks regular-file success, invalid/retired descriptor EBADF and pipe EINVAL. The raw API must preserve errno and retain descriptor ownership, file identity/size/position and descriptor/status flags. Both products require EH and `-fno-exceptions` builds from one frozen source/provider closure.

`posix_nothrow_fdatasync_enosys.cc` is a separate single-threaded native Linux x86_64 test process. It uses the target SDK's audit architecture, x32 bit, field offsets, filter structure and syscall numbers, sets its own no-new-privileges bit, then installs a filter on itself that returns real kernel-filter ENOSYS for fdatasync. The original supervisor and cgroup are unaffected; no child or thread is created, and the filter ends when that process retires. An independent libc call and the raw API must both expose ENOSYS, while a separate explicit fast_io fsync succeeds. Silent fallback inside the API would fail the ENOSYS assertion. Filter installation failure is a failed/unavailable qualification, never a skipped PASS. This is failure-injection behavior, not proof of an absent syscall on an old kernel; other architectures need separate seccomp qualification.

`posix_nothrow_fdatasync_module_consumer.cc` requires a fresh same-profile fast_io PCM and object and calls the exported operation/result through an import-only TU. No forced header injection or old PCM reuse is permitted. Its invalid-descriptor errors are compared with the existing fsync export; the separate SDK unit supplies the independent native oracle.

The sole SSH Linux keeper owns all execution in the shared 64 GiB cgroup. The ordinary/ROS EH/noEH plan, compiler dependency/provider identities, raw output, original supervisor/PIDFD resource and retirement evidence belong in the test record. No Mac test is authorized for this candidate. Cancellation/EINTR, persistent-filesystem writeback errors, other libcs/architectures, seccomp under QEMU, and the Linux libc fallback remain pending independent qualification.

Primary references: [Linux fsync/fdatasync manual](https://man7.org/linux/man-pages/man2/fsync.2.html), [Linux 6.17 sync implementation](https://raw.githubusercontent.com/torvalds/linux/v6.17/fs/sync.c), [glibc public unistd declarations](https://raw.githubusercontent.com/bminor/glibc/master/posix/unistd.h), [glibc fdatasync implementation](https://raw.githubusercontent.com/bminor/glibc/master/sysdeps/unix/sysv/linux/fdatasync.c), and [Linux seccomp manual](https://man7.org/linux/man-pages/man2/seccomp.2.html). These were read for operation semantics, the scalar ABI and the isolated failure-injection mechanism.
