# Host-provider memory64 bulk source candidate

This private candidate fixes a genuine LLVM emitter gap: a host/type-erased imported memory has no `runtime_native_memory_t*`, but the prior memory64 `fill` and `init` emitter required one unconditionally. Ordinary Wasm imports resolving to a native memory were already supported and do not qualify this host-provider branch.

The candidate adds two cold provider64 bridges and only two selected64 emission branches. Existing native64 bodies are unchanged apart from indentation inside a qualification `if`; memory32 bodies, the complete checkpoint emitter prefix, five normalized dispatcher slots, register-ring code, and validator code are unchanged. No ordinary memory access gains a guard, lock, or instruction. Existing relocation/execution leases and provider callback policy still own object lifetime.

`fill` preserves unsigned i64 destination/length until the complete destination range is proved. Only then can length narrow to `size_t`, and provider writes use a fixed 4096-byte staging buffer. `init` preserves its i64 destination and actual i32 source/length carriers, validates the actual data-instance index and stable drop-aware payload, checks both complete ranges before any provider write, and skips pointer addition on the empty path. Zero-length instructions still check their bounds. A provider snapshot's raw allocation pointer is never retained by either bridge.

The authoritative Core 3 semantics are [memory.init](https://webassembly.github.io/spec/core/exec/instructions.html#exec-memory-init) and [memory.fill](https://webassembly.github.io/spec/core/exec/instructions.html#exec-memory-fill). Native host-provider failure after a previously valid callback write follows the existing provider callback contract; this candidate does not claim transactional rollback for arbitrary faulty host providers.

The real fixture imports one i64-addressed page from the actual `local_imported_t` host API. Its memory is a real `fast_io::native_file` plus `native_file_loader` shared mapping, retained through owned `shared_ptr` backing. The external Python runner creates a fresh file/process for every case and compares all 65536 backing bytes after a trap. This tests partial-write rejection without drawing a false conclusion from fork/COW isolation. The fixture uses fast_io scanners, output, file ownership, and mapping APIs; it introduces no raw operating-system call or custom C++ decimal/LEB decoder. Official WABT assembles the latest memory64 WAT through `--enable-all`.

There are eleven actual Wasm functions: two valid functions, and nine bounds cases covering high destinations with zero length, high fill length, unsigned maximum destination, crossing the final byte, an invalid zero-length data source, and an actual dropped data source. A 5000-byte valid fill crosses the staging boundary and truncates the value 421 to byte 165. Memory64 only needs one genuine page; a fake sparse provider never reports a huge allocation backed by a tiny buffer.

Qualification is still pending. Source/Python checks are not C++ compilation, LLVM IR verification, module compilation, generated code inspection, runtime execution, or performance. The analyzed compiler module and subsequent actual full-runtime materialization are different objects; no receipt conflates them. The runner keeps `physical_runtime_codegen_qualified=false` until the sole Linux keeper binds the fresh component and all runtime translation units to the exact new source/SDK/provider closure and inspects an actual materialized body. The symbol-based analyzed-IR witness deliberately fails on a target that lowers bridge pointers without symbols instead of silently reporting success.

Run only under the existing Linux keeper's 64 GiB cgroup and admission guard. The finite recipe is: assemble the exact WAT once, fresh-build the C++ fixture and all matching LLVM-full runtime translation units for each repository/provider, run `run.py --wat2wasm <official-tool> --component <ordinary-component> --component <ros-component> --output <new-dir>`, then inspect actual runtime JIT objects/host bridge bodies from separately qualified capture runs. No native work is authorized on the Mac by this packet. Header and standalone module closure checks remain separate; this candidate does not repair or hide unrelated default lazy/tiered second raw-decode gaps.
