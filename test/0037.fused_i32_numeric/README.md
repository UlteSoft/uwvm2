# First-decode i32 numeric events, source proposal

All 18 primary opcodes 0x67–0x78 share the actual Core3 pop_core3_operand_sequence transition. Pure Wasm3, int full/lazy and LLVM full/lazy supply owned normalized abstract operands. The dispatcher bounds and reads the opcode once; the adapter advances exactly one byte and never reads it again. Successful validation emits a copied event with opcode, arity, byte effect, current-frame stack polymorphism, source extent and control depth. LLVM consumes that event directly, with no raw slice fallback for this family. Interpreter ring/combine/musttail emission is unchanged except for its validation call.

The LLVM bodies are mechanically moved from the original inline cases. Zero-defined clz/ctz, modular arithmetic, division-zero traps, signed division overflow, signed remainder min/-1 diamond, count masking and rotations retain their original IR expressions. Event preflight checks compiler consistency and adds no generated guest guard, lock or poll. Existing fused dispatch observes provenance/debug/checkpoint before consuming operands; its transaction commits only after successful same-op validation/lowering. An event is compiler DATA, not publication, guest, native-debug or restore authority. Complete function validation still precedes publication. Unsupported emission retains the existing rollback/fallback contract without raw replay.

The R2 source correction preserves the immutable unapplied R1. Validator child-frame entry resets local stack polymorphism even under dead parents; that flag is not physical LLVM reachability. The event names this distinction explicitly. LLVM checks logical control depth against the bounded sum of actual physical control entries and its existing skipped-unreachable depth. The original unary/binary helpers suppress physical dead IR. Every opcode's real LLVM component now tests a non-polymorphic logical child below two skipped dead frames and mismatched-depth no-mutation rejection; the actual WAST also includes genuine nested block/loop dead-parent bodies. These remain source fixtures until executed by the keeper.

R3 rebases narrowly on the actual applied atomic and bulk-memory sources. Existing five normalized bool/event slots remain in order; i32 appends the sixth specialization. Its wrapper receives only an owned event and supplies null raw pointers. Pure event consistency preflight runs before provenance/pending/debug metadata or body IR. The original i32 pure-carrier rule remains; no new retirement/root poll is emitted. The actual LLVM49 component now calls this real sixth wrapper with a live owned compiler fixture local_func_storage_t and ordinary debug/pending hooks disabled. That owner has no raw source, parsed module or stop capability and grants none. Genuine decoded-source/full-function publication qualification still belongs to the fresh product CLI and module build.
