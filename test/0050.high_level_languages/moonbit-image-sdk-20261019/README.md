# MoonBit typed Image: finite Linux qualification

This checkpoint adds a real typed Image codec and resource methods to the ROS
SDK. It qualifies a finite compiler/model/Runtime/source-map matrix. The original
fifteen-language requirement bundle remains incomplete: no new positive native
ROS Image delivery, complete official client-library parity, hardware performance,
QEMU/platform, cache-update or arbitrary MoonBit object-debugging claim is made.

All compilers, validators, models, Guest/native/reference targets, debugger
sessions and the independent reader ran over SSH Linux in the original existing
hard64GiB/swap0 cgroup. macOS only edited/read source and transported/hashed inert
data. No other agent or thread was contacted.

## Implementation

wire/image.mbt supplies Image.validate/encode, read_image and to_mono8. Both ROS
packages add Resource.write_image and Resource.poll_image without changing the
base ABI or grants. The canonical codec preserves complete u32 ROS1 timestamps,
bounds ROS2 seconds and explicitly requires ROS2 sequence zero. It checks the six
supported encodings, full frame/stride/dimension/data relationships, exact Bool,
truncation/trailing bytes and the4193786-byte input bound before narrowing.
The native Host accepts nonzero ROS2 canonical sequence bits; the SDK profile
deliberately refuses their lossy projection to ROS2 Header.

Conversion respects RGB/BGR, row padding and ignored alpha, produces packed
mono8, preserves the header and leaves input bytes unchanged. mono16 conversion
explicitly refuses95. All typed resource effects still use exact operator grants,
checked owned handles and existing cleanup; no native pointer, managed-object
address, grant or retry is invented.

The two new ROS examples process a padded2x2 RGB fixture and check complete
Image round trips/cleanup. Empty aliases are the default. The third new example
uses no ROS import. The current English Image guide documents all fields,
methods, errors, compiler commands, ownership, native-scene acceptance gates,
source-map relinking, old native libraries and the debugger-option boundary.
Ordinary/stable receive this identical evidence without active ROS SDK coupling.

## Debugger qualification and source-path correction

The producer's ordinary --debug application has names but no source line
metadata. A separate actual moonc link-core command adds an adjacent Source Map
v3 and absolute -pkg-sources paths. The initial relative-source map resolved
against the sidecar directory and the requested source breakpoint refused.
The corrected relink leaves the complete Code section unchanged. The retained
old failure is not relabelled.

All three accepted sessions stop at the actual image.mbt line118, repeat the
same read-only unavailable-value query, delete the breakpoint, step by source,
observe a newer stop-id, refuse a stale read, finish the complete Guest
success marker and close the console normally. Their owned groups close with
no success-path cleanup signals or retirement errors.

The value query explicitly reports no usable source variable/type information.
Source Map v3 supplies locations and stepping; it does not decode MoonBit
lexical objects or GC values. finite_full_value_workflow=false is intentional
and truthful; finite_source_map_workflow=true supplies the actual accepted
scope. This cohort does not qualify GC source debugging, ROS callback debugging,
all frontends or full high-level language debugging.

The all-disabled ROS LLVM product still runs the legitimate pure MoonBit
artifacts. Existing fifteen xmake switches/macros default on and control host
debug adaptation, not a Guest-language execution whitelist. Keeping the other
language debug adapters enabled is recommended.
