## Implemented application and policy

The application independently opens a granted `tf.lookup` owner for `/tf` and
a granted `tf.broadcast` owner for `/tf_static`. A native source publishes a
TFMessage containing both the authorized `map/base_link` record and an
ungranted `map/forbidden_link` record. The Guest requests one timestamp, checks
every field in the complete authorized reply, adds one metre to x and emits
`map/processed_link`. The independent native witness checks the entire final
value, source/writer identity, endpoint graph, forbidden-effect absence and
retirement. Lookup-only and broadcast-only profiles test each grant separately;
the zero profile has neither native endpoint. Scheduling stdin bytes convey no
frame, connection, credential, capability or memory authority.

`sdk/tools/tf_policy.py` prepares reviewable argv/configuration without launching
a process or applying authority. Each operation requires explicit selection,
frame pair and resource. It serializes backend-specific trusted type IDs,
connection/authentication fields and finite quotas. It reuses only the existing
zero-topic-grant connection serializer. The final profile uses timeout 5000ms,
depth/burst 4, one in-flight request, max-message 586, queue 4096 and explicit
translation/quaternion bounds. The64 real scenes validate the generated selected
policies; a separate exhaustive malformed-CLI/parser corpus is not claimed.

The selected `/tf_static` publication is explicitly non-latched on ROS1 and
reliable/volatile on ROS2. It qualifies current matched-peer delivery, not
standard retained static-TF delivery to late joiners. This finite application
does not implement full tf2 interpolation/history/extrapolation or official
rcl/rclcpp/rclpy/rcljava API parity. Native shared/static libraries remain native
Gateway/driver dependencies or require compatible source recompilation; they
cannot be loaded into the Wasm Guest to obtain native process authority.

R1 completed one zero scene, then refused a burst 32/depth 4 policy with
`BLOCKED conflicting limits`. The corrected policy narrows burst to 4.

expected an empty 1500ms lookup to return110 and leave its native listener ready

unqualified. Earlier zero scenes are not added to the final 64-scene total.
