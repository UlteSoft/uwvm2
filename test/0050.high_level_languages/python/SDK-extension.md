The producer exposes a static CPython embedding extension point. The ROS SDK owns its ABI wrappers and native extension implementation; this directory does not implement them. [SDK-reuse.md](SDK-reuse.md) gives the actual retained build paths, precise inittab/relink recipe and separate full-stdlib file contract.

Compile `embedded_main.c` with `-DHLL_EXTENSION_HEADER=\"roswasm_inittab.h\"`, add the directory containing that SDK-owned header to include paths, and link the SDK's extension objects into the same final Wasm. The header can declare `PyMODINIT_FUNC PyInit__roswasm_native(void);` and define `HLL_REGISTER_EXTENSIONS()` as `PyImport_AppendInittab("_roswasm_native", PyInit__roswasm_native)`. The hook runs before CPython preinitialization. Default builds register no extra extension and need no ROS imports.

The SDK extension may accept ordinary Python bytes/memoryview objects, obtain a checked `Py_buffer` for a synchronous call, copy serialized bytes into its Wasm linear-memory arena and invoke the numeric ROS ABI. Keep explicit offset/length bounds, principal/handle/ticket scope, buffer lifetime and error conversion; do not expose a retained pointer after `PyBuffer_Release`. ROS message schema and serialization belong to the SDK. A pure Python bytes encoder can be frozen alongside the application without requiring a filesystem. The fixture already tests bytes ownership and a memoryview retaining its backing object.

The base recipe makes no `_ctypes`, libffi, dynamic extension, pip, socket, subprocess or Python-source debugger claim. A statically registered C extension is the intended reuse route. UWVM DBG qualification will cover real Wasm/native entry, instruction step, stack, breakpoint, restart and output. CPython C-frame DWARF does not supply Python local variables. A future `sys.settrace` bridge needs its own before-line/value and restart qualification; it is separate from the Wasm debugger and is not part of the current base fixture.
