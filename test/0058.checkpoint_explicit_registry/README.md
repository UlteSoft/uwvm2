# Explicit LLVM-full compilation registry (source proposal)

This packet supplies one real prerequisite for fresh-world checkpoint restoration: the existing fused LLVM compiler can borrow a particular actual registry without selecting it as the global active runtime. It is not a fresh-world restore implementation or an executable admission token.

`compile_option::compiler_registry` is a native, readonly, full-only metadata borrow. The ordinary null option retains the old active registry. Each actual function compile checks the requested module's exact registry membership, temporarily stores that borrow in its descriptor, and forwards it to direct/tail alias resolution and the resumable direct-import owned-child witness. The original single Wasm validation/emission traversal, declared type matching, normal guest instructions, memory guards, exception ABI and musttail emission are unchanged. The temporary descriptor borrow is cleared immediately after that fused call; returned compilation DATA never carries this outer registry pointer. No source image is parsed or body separately decoded by this adapter.

For the explicit world, each imported alias cursor and its final defined record must name an exact registry vector element before it is read or advanced. The finite alias bound comes from the same registry. Neither weak ownership, a native executable address, the globally selected source nor a caller-provided readiness flag substitutes for this element proof. The native owner must retain the nonmoving registry, final parsed files and resolved records unchanged through all compiler workers and their join.

The new `registry_borrow.cc` is a native compiler metadata regression. It deliberately installs an unrelated test registry as active, then checks a nine-record private alias chain, provider type resolution, nonmember-world refusal, the selected resumable owned-child witness, ordinary null behavior, cyclic aliases, foreign records, interior pointers and observation-profile refusal. These actual C++ records are not an initialized source or a validated Wasm module. The test never creates a native entry or code owner and never publishes an epoch. The active selector is restored with RAII.

A later actual restoration transaction must still complete and prove the entire module/type/alias/root/segment/memory graph; pin the canonical fresh source and its per-function effective parsed code/generation; compile and verify genuine typed plans; privately create and finalize a cache-disabled LLVM engine; drain the real old world; then perform the single real source/resource/epoch/code publication. The old global full materializer cannot establish that preparation. This packet contains none of those permissions and does not relax any initialized source seal.

No cache revision is changed: ordinary null-context accepted code and emitted IR are unchanged, and debug-full objects already exclude persistent cache use. The explicit source-world engine path must keep cache disabled because its generated resource/typed-slot addresses belong to its actual private world.

Native compilation/execution, LLVM verifier, module/BMI closure, assembly, official parsing and performance all remain unrun. Only `/root/linux_native` may run these targets in the existing guarded 64 GiB Linux cgroup. Planned checks are both products' new metadata unit plus actual fresh source/context module fixtures and existing full/tail/import/debug/checkpoint regression once the genuine transaction consumer exists. Do not report metadata success as complete checkpoint restoration.

Primary references: Core 3 store/instance and function invocation semantics at https://webassembly.github.io/spec/core/exec/runtime.html and https://webassembly.github.io/spec/core/exec/instructions.html; LLVM execution engine ownership and finalization at https://llvm.org/docs/MCJITDesignAndImplementation.html. The changes borrow real compiler inputs rather than serialize or reinterpret host pointers as guest state.

R2 narrows R1 lifetime/proof wording: explicit module membership is checked before module-vector/type/code reads, and the temporary compiler registry pointer is cleared before returning compiled metadata. The source preimages remain the frozen actual-current R1 pins. R1 was not applied or executed.
