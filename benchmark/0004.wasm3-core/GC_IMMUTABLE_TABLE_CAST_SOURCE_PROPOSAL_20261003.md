# Immutable table ring: source proposal awaiting actual assembly

This is a read-only design proposal. No production helper, translator, validator, feature default, benchmark count or original measurement guard is changed by this packet. `execute_ready=false`. Its source observations are separately pinned in `gc_immutable_table_cast_source_pins_20261003.json`; they do not identify a newly built product or qualify an optimization. Native implementation and measurement require the fresh full-product assembly described below.

## Scope and current evidence

The target is the original `gc-allocation-ring` workload: 16,000,000 iterations, 1,024 exported table roots, immutable single-i32-field structs, Wasm SHA-256 `66874f9a4a0a5977b4ace1cc702f949c6c2627311dce0bcbe87c818c55516e3e`, returned state `493211925`. Its loop contains allocation, `table.set`, `table.get`, `ref.cast`, and `struct.get`. The recently qualified native 4M-allocation component instead declares mutable fields and writes a native root array. Its approximately 5.2% single-CAS improvement cannot establish an improvement to this Wasm chain.

The current source already has an immutable cast witness and an adjacent getter that consumes it through one native 32-bit load. It also already has allocation co-location and experimental managed/sealed alternatives. Those are not new proposals. For the ordinary legacy object path, the source suggests a remaining repeat: `table.get` calls `uwvm2_gc_retain_reference`, whose local branch authenticates a member; the following immutable `ref.cast` authenticates that same local member again before checking its canonical type and readable immutable prefix. Source structure alone does not prove that the new product executes both walks.

## Assembly gate before implementation

Use the parent-owned fresh full-product cut, not an older ELF renamed as current. Keeper captures the actual single-module MCJIT object in an untimed run, using the existing test-only capture hook, an exclusive output path, `-Rct 0`, cache disabled, and the exact Wasm above. Ordinary and ROS instruction/unwind runs need separate ELF/source/provider identities. Capture remains disabled in every timed run. There is no existing public IR-dump option to assume.

Inspect the actual function-zero loop, object relocations, and the matching current ELF's table-get, retention and immutable-cast callees. Record complete symbols or address-to-symbol evidence for process-local helper addresses. Determine whether both local membership loops execute, whether table-family classification is already collapsed by host O3, and whether the existing adjacent getter is actually one load. An unresolved address, an older host callee, or source-only IR cannot satisfy this gate. CFI and each real trap site's native-to-Wasm mapping must also be identified for the selected call-stack strategy.

## Candidate A: one authentication for the adjacent get and cast

The proposed operation returns the complete original Wasm reference and the existing private cast witness, rather than exposing a checked header in a Wasm local or table. Its fast branch performs actual table resolution and unsigned full-width bounds checking first. After genuine local membership authentication, a private checked view can satisfy the local caller-retention check and the cast's canonical-owner/type and immutable-prefix checks once. A local successful cast can return the existing `0` / `1` / `>1` witness convention; the existing immediate getter remains its sole borrow consumer. This is a hypothesis until actual assembly shows repeated authentication.

The first candidate must conservatively require an actual local-defined GC table owned by the executing module, an actual object in that module's live store, and a validated immutable 1..8-field i32/f32/packed target accepted by the existing witness rules. A declared union kind, a table index, a token's address shape or a canonical type index alone is insufficient. Imported tables, foreign owners, handoff/retirement, null, arrays, external/exception/function references, unsupported geometry and other profiles retain their original resolution, full-carrier conversion, caller-root transfer, leases and cast/get fallback. A foreign value must never be returned as a borrowed field address.

Bounds failure must stay at `table.get`; a cast mismatch is returned as private status and traps at the original `ref.cast` site. Nullable success remains a successful cast with no field borrow, so a following getter still performs its original null trap. These follow the Core 3 execution rules for [table access](https://webassembly.github.io/spec/core/exec/instructions.html#exec-table-get), [reference casts](https://webassembly.github.io/spec/core/exec/instructions.html#exec-ref-cast), and [struct field access](https://webassembly.github.io/spec/core/exec/instructions.html#exec-struct-get).

Do not pre-parse or skip a future Wasm instruction to choose this path. Both instructions must pass the same existing single-pass validation and immediate decoding. At the already validated cast, the compiler may consider replacing only a recorded, exact previous table-get IR producer. Such replacement is legal only if the complete emitted interval is proved free of observable actions: no call, poll, root publication/generation change, allocation, mutation, control-flow edge, handler change, checkpoint, trace callback or instruction/debug transition may be crossed. Merely observing the same SSA reference is insufficient. The complete Wasm reference remains live and rooted according to the original runtime policy. Any inability to prove eligibility preserves the original sequence.

The existing cast-to-get rule remains unchanged: exact next Wasm byte offset, exact target, immutable field, same empty cast-success block, checked readable extent, and no intervening emitted operation. The local checked view does not persist across runtime calls or safepoints. No ordinary access guard, lock, global cache, TLS capability lookup or persistent generation field is introduced to justify it.

The initial experiment is disabled for selected debug, instruction tracing, checkpoint/replay and patchable/debug activation profiles; their real pre-opcode state and native-to-Wasm provenance remain ordinary. Instruction and unwind diagnostics still need their distinct original get/cast failure sites. Changing either site's identity, hiding an observable instruction boundary, or borrowing through a generated helper/callback rejects the candidate. An unwind frame policy is not permission to merge error PCs or remove CFI.

## Candidate B: validated family specialization

A narrower alternative is a GC-family table bridge selected from validated table metadata. It could omit repeated function/external/exception/GC family classification while retaining actual table resolution, pointer ownership, bounds checks, complete carrier conversion, root retention and debug-table exclusion. Table width is already selected by the compiler. Imported declarations still require their resolved provider table and owner/type compatibility. This is worth implementing only if the actual matching host assembly retains classification work; host O3 may already eliminate it. It does not replace canonical membership or foreign retention.

## Acceptance after a separately reviewed source candidate

Keep the experiment default off and independently identified. Small correctness gates must exercise successful local and proper-subtype casts, mismatch, null with nullable/non-null casts and getters, table32/table64 bounds, packed signed/unsigned and f32 bit patterns, imported foreign table clear/provider retirement, stale/forged host-boundary references, and concurrent actual publisher/foreign handoff. These must use genuine runtime ownership and canonical admission; fabricated pointers or mocks cannot establish safety. Debug/checkpoint/trace exclusions require actual generated-code checks, as do accurate get/cast/get error PCs under instruction and unwind policies.

Only then compare the exact original 16M Wasm in fresh ordinary and ROS full products on the same P-core, with genuine wall-clock ROI, independent state/root oracles, memory/OOM evidence, actual frequency series and qualified hardware counters. Whole-process hardware counts include setup and final reclamation unless a separate real ROI mechanism proves otherwise. Same-platform Wasmtime/WAVM results remain separate until actually built and measured from pinned source/configuration. A component speedup, a reduced collector scan, or one different source's assembly cannot be reported as fixing the original 117ns/step observation or surpassing another VM.
