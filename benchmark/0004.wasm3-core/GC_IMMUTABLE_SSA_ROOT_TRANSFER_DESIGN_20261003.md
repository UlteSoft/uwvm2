# Immutable ring: authentication reuse and precise SSA roots

This is a read-only source design. No runtime, translator, validator, macro, object layout or benchmark count is changed. Implementation eligibility awaits the current product's actual captured JIT object and matching host helper assembly. The selected live source pins are observations, not a full build closure, an execution permission or a performance result.

## Existing work that must not be counted twice

The original immutable ring is 16,000,000 iterations, 1,024 exported table roots, one immutable i32 field, state 493211925 and Wasm SHA-256 `66874f9a4a0a5977b4ace1cc702f949c6c2627311dce0bcbe87c818c55516e3e`. Its allocation, table.set, table.get, ref.cast and struct.get all remain observable. The exact workload and proposed adjacent table/cast specialization are described in [the existing source proposal](GC_IMMUTABLE_TABLE_CAST_SOURCE_PROPOSAL_20261003.md).

The existing immutable cast/get witness already permits one checked immediate numeric load. The root emitter also already removes every compiler-owned root-frame instruction when its final maximum root count is zero. `finalize_runtime_local_func_llvm_jit_emit_state` calls `finalize_runtime_llvm_jit_gc_root_frame(..., true)` after wrapper and cold-edge construction. The latter verifies that every root instruction and its users belong to the owned set before erasing them. Therefore removing an empty frame or repeated zero-count publications is an existing mechanism, not a new optimization. Capture must establish whether this mechanism already removes the original ring's root IR.

## Source-to-machine proof to collect

The live ordinary local table.get path resolves the actual table, checks the full-width index, converts the complete carrier and calls checked caller retention. Local retention uses `checked_object`, whose first branch calls `checked_local_object`. The next immutable cast calls `checked_local_object` before canonical subtype and immutable-prefix checks. Two source calls do not prove two machine walks: inspect the exact current JIT object relocations, matching full ELF helper bodies and hot-loop call destinations before selecting a change. Keep unresolved native addresses unknown.

At each allocation/call/poll, identify actual slot stores and live-count publication. The ordinary allocation path snapshots before consuming its reference arguments. The runtime frame entry initially sets live_count to zero. Slots are complete tagged carriers, not raw token addresses. The collector reads them only after the existing participant/cohort pause and validates the whole frame chain before delivering roots. This mechanism does not authorize skipping owner authentication, foreign leases, precise table/global roots or failed-graph preflight.

Capture is untimed only: fresh aligned main/runtime/host, exact source and macro vector, original Wasm, cache disabled, separate instruction/unwind profiles and separate ordinary/ROS products. Every plain/HW/VTune measurement clears the capture environment. The GC31 metadata ABI is a separate new source cut; an old console product cannot prove its declarations-after behavior. Historical map-backed non-TLS percentages do not identify the fresh native-TLS product's bottleneck.

## First possible change: reuse one actual local authentication

If assembly confirms both walks, consider one composite table-read/cast operation at the already validated adjacent cast. Use the original table read's actual successful lookup to provide a private checked local view to canonical cast verification within the same native operation. Do not emit a new preliminary probe. The view originates only after the original lookup and kind/owner checks; it is neither a guest value nor a transferable token. It dies before the helper returns. The output remains the original complete reference and the existing 0/failure, 1/no-borrow or greater-than-1/immediate-field witness.

The first fast branch requires an actual local-defined GC table and actual ordinary local object in the executing store; canonical subtype, target field layout and immutable readable extent are still checked. Imported or foreign tables/objects, compact/page/sealed profiles, stale/forged values, exn/extern/func, unsupported layouts and managed/debug/checkpoint boundaries use the original retention/cast sequence. Do not turn a foreign lookup miss into permission, or acquire a lease twice. Same canonical type, module declaration, token shape or successful allocation at an earlier safepoint is insufficient.

An actual bounds failure remains at table.get. Cast failure remains a private result and traps at the original ref.cast; nullable success has no field borrow and the original following null getter still traps. Preserve separate native-to-Wasm trap identities and CFI. Both opcodes still pass normal single-pass validation and immediate decoding. The compiler may rewrite only an exact retained previous producer in the same proved interval after validating the cast; it never pre-parses the next instruction. Any intervening call, allocation, poll, root publication, mutation, control/handler edge, trace/debug/checkpoint event or unclassified effect declines the rewrite. Never forward table.set into table.get without real mutator exclusion.

This is one candidate, not combined with root compaction or allocation changes. A separately reviewed default-off profile and versioned bridge/cache identity are needed only if the machine evidence justifies implementation. Register-wide ABI, exact FunctionType/calling convention and actual host symbol rebinding must be checked on each admitted architecture. O3 failure to eliminate a walk must not be inferred from source names.

## Independent later candidate: duplicates in one root snapshot

Consider this only if real code contains repeated nonzero root slots. At one publication, keep the first occurrence of each exactly identical complete LLVM SSA reference. Identity means the same LLVM Value and carrier width at this snapshot; it does not mean the same declared type, alloca address, token payload or a value from a previous publication. Different loads from one local remain different until genuine compiler reaching-definition proof exists. Do not invent equality across PHIs, EH/call continuations or loop iterations.

Validate every original input's carrier type, dominance and original capacity/overflow bounds before considering deduplication; preserve first-occurrence order. Emit each retained complete carrier into fresh frame-owned slots and publish the final distinct count only after those stores. Record original versus distinct count because root-visit diagnostics change. This does not change object reachability, but must not bypass a rejected original capacity/admission condition or remove a later invalid distinct root. Numeric/v128 values are never roots by bit pattern. No witness, pointer or source authorization survives the publication.

Keep root-frame enrollment, enter/leave, host/tail/EH cleanup, precise table/global/native roots, retained owners, generation/epoch and exclusive collection protocols unchanged. Do not reuse a prior snapshot after a call or safepoint merely because source operands look equal. Moving-GC adoption would require writable relocated roots and a new pointer/handle contract; this design does not provide that. The original immutable ring may have no candidate root duplicates after existing empty-frame deletion, in which case no root optimization should be implemented for it.

## Relevant primary implementations and limits

Pinned Wasmtime v49.0.1 commit `46c23a87dac1465986a8ad53ba6a7ae49372857b` emits inline bump allocation with widened alignment/end arithmetic, a cold allocation libcall and a stack-map declaration for the resulting reference. Its no-barrier path belongs to a moving stop-the-world heap contract. This explains a different cost structure; it does not justify removing our cross-store identity/lease checks. [Copying compiler source](https://raw.githubusercontent.com/bytecodealliance/wasmtime/46c23a87dac1465986a8ad53ba6a7ae49372857b/crates/cranelift/src/func_environ/gc/copying.rs).

The same pinned runtime processes a Cheney worklist, forwards live objects and updates roots. It also guards collection against an active no-GC scope. Our nonmoving opaque-key membership and retained foreign owners are different contracts; replacing local hash walks with unchecked guest pointers would not reproduce that design safely. [Copying runtime source](https://raw.githubusercontent.com/bytecodealliance/wasmtime/46c23a87dac1465986a8ad53ba6a7ae49372857b/crates/wasmtime/src/runtime/vm/gc/enabled/copying.rs).

Immix combines contiguous allocation with block/line reclamation and selective evacuation that accommodates pinning. It motivates a future arena/layout investigation, not the proposed single-operation authentication reuse, and its published speedups are not measurements of this VM. [Immix primary paper](https://www.steveblackburn.org/pubs/papers/immix-pldi-2008.pdf).

## Small acceptance path after source review

First inspect the current original 16M JIT loop and matching helpers. If there is no duplicated walk/root work, record that result and decline the candidate. Otherwise implement only the selected operation and capture before/after optimized IR/object/host assembly in untimed runs. Preserve generic failure and cold fallback blocks, actual error PCs and immediate getter bounds. Do not obtain a speedup by changing benchmark bytes, collector thresholds or root count.

Then use small real local/subtype/null/mismatch/packed/f32 cases plus genuine imported-provider retirement, stale/forged tokens, collection/reset and concurrent owner controls. For root compaction, include duplicate and distinct reference parameters/locals, mixed numeric/v128, loop PHIs, retained foreign and exception values, later invalid roots and actual EH/tail cleanup. Graph errors must still reclaim zero objects. Only keeper executes native tests.

Finally run the unchanged workload through unprofiled internal Wasm timer plus parent wall/user/sys, whole-guest single-TID hardware counts with exact enabled/running/FD proof, and independent target-P0 VTune. The internal Wasm timer excludes initialization/JIT but includes all guest setup/readback/collection; whole-guest counters include initialization/JIT. Neither is a collector-only ROI. Temperature is recorded only. Frequency snapshots are not effective ROI frequency. No present source proposal establishes an improvement to 117ns/step or a ranking against Wasmtime/WAVM.
