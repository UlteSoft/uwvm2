# Current Ordinary EH/thread command recipe, 2026-10-02

This is a source-only command producer for the actual completed Ordinary R3c
three-TU build. It executes no compiler, guest, profiler, SSH or supervisor.
ROS is deliberately unsupported until the corrected R3e full source and actual
build-after receive a separate binding; failed R3d objects cannot be admitted.
The existing Linux keeper remains the sole executor.

Run `prepare_current_EH_thread_commands.py prepare` in the admitted Linux scope
after reviewing this source. It verifies the fixed R3c source ID, actual build
closure, three component objects/MD/header pins, tools, libraries and SDK/RSP;
then creates a fresh `builds/current-R3c-EH-thread-commands-20261002-r1` directory.
The files contain twelve EH cold cells and three thread fixture compile/link
pairs. No new runtime compilation profile, collector macro or public ABI is
introduced. The thread selector macro applies only to the test helper; the
qualifier-only pthread-create interposition must be absent from the timed ELF.

The keeper must bind each new fixture MD/object/link and the actual complete
supervisor receipts before executing it. This producer marks that qualification
pending; it does not mistake generated commands for completed builds. The same
runtime and host-api objects may be reused only from the fixed actual R3c parent.
CLI main.o is never linked into a thread fixture. Capture is stripped and the
actual stopped-child environment must prove it absent, as in the current guard.

Execute `eh-cold-commands.json` using the existing bounded supervisor first.
The exact three original binaries assert the LCG checksum and, for eh_throws,
500,000 real callee-to-caller catches. Both trace policies and both exception
dispatch controls are tested. Record actual dispatch selection, not just argv.
These command vectors are functional syntax; a later P0 plain adapter must put
loader/capture settings into the real child environment and authenticate the
actual executable. Its guest vector starts `taskset -c 0 ACTUAL_CLI ...`.
No private-leaf candidate, delayed trace contract or software counter is added.

The `thread-cold-commands.json` qualifier checks real create counts under both
policies and dumps shared-memory/atomic.fence binaries for actual official
validation. The parked fixture separately dumps/validates its wait32/notify
module. Keep fresh dump paths, source and exact byte hashes. Before timing,
actual nm/symbol evidence must prove that the timed fixture has no pthread_create
interposition while the qualifier does. Preserve the completed cold assertions.

`thread-plain-commands.json` uses the qualified timed executable: nine samples,
1,024 rounds with two warmups for each creation/work/join configuration; genuine
parked notify uses its existing nine samples of 128 wakes after two warmups.
Creation runs use P0; parked notifier/waiter use P0/P2. Every owned TID still needs
actual UID/cgroup/allowed-core/retirement evidence. These multi-TID processes
must not be inserted into the frozen single-TID hardware counting protocol.
Thread internal warmed ROIs differ from whole-process wait4 wall/user/sys/RSS.
The internal Wasm EH timer excludes startup/JIT, includes the entire workload,
and is not a pure unwinder or collector timer. Temperature remains raw
observation; frequency, actual identity/resource proof and noise limits remain.

The initial actual measurements are pending. The final CLI signed-cache hit,
EH trace retention/catch_ref/rethrow cases and thread stress matrices retain
their own qualification and cannot be inferred from this narrow command list.
