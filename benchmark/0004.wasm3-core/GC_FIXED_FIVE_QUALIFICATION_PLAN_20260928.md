## Actual emitter and MCJIT check

`test/0014.llvm_jit/llvm_jit_gc_aggregate_callsite_ir.cc` includes the actual product `compile_all_from_uwvm/impl.h`, uses real `wasm_module_storage_t`/GC layouts/segments, and calls `try_emit_runtime_local_func_llvm_jit_gc_aggregate`. A one-header `-I` overlay cannot override the emitter's relative include. `run_gc_aggregate_callsite_ir.py` therefore accepts only an actual, source-matched product tree and O3 build; it requires both the exact source ID and actual emitter SHA.

The 49 generated functions cover all 20 aggregate opcodes; struct/array fixed creation with 0–9 inputs; 128/129-input cases on the 2048-byte stack/heap boundary; packed fields; all six scalar/reference carriers; passive data and element segment index one; and different compatible source/destination array types. The checks verify the real function address registration, five/seven-argument LLVM `FunctionType`, calling convention, metadata order, complete 16-byte slot initialization, preserved operand-stack prefix, byte-safe typed stores/loads, scratch allocation/free ordering and trap-edge dominance. The actual linked SDK runs the O3 pass pipeline, verifies the IR and machine-code generation, and emits an ELF object with relocations and assembly.

MCJIT executes each generated helper through a test-only integer-address entry. A direct call to the actual generic native bridge acts as the ABI/marshalling oracle. It uses a separate set of real objects from the JIT path, so a reference write cannot pre-populate the JIT target and hide a missing store. Every field, array length/element, scalar/vector bit pattern and reference identity is compared. This oracle checks the LLVM/native boundary; it is not independent Core 3 semantic conformance. No module is parsed or validated by this fixture, and no collection occurs.

As of this preparation, only Python syntax and command-adaptation self-tests have run. The new C++ fixture has **not** been compiled, verified, linked or executed; actual LLVM/MCJIT/object qualification remains pending. The runner must run after the exclusive remote build window is released. It retains the selected SDK response-file hashes, source fingerprints before/after, product/runtime/fixture/emitter hashes, commands, actual IR/object/probe artifacts, resource samples and true exit status. Object readers may be external tools; optimization and object generation use the actual linked product SDK. Compilation runs on E cores; functional MCJIT execution on P0 is explicitly non-timed qualification.

Record startup separately from steady-state work, raw sample duration, allocation totals, process RSS, cgroup OOM/throttle counters, exact 4P/16E cpuset, frequency/governor snapshots and available temperatures. Extend short samples or label them too short. Re-run in a comparable thermal range if drift obscures a small effect. Run the explicit release gate: real collection count, live-root/cycle safety and RSS plateau must pass before GC release can pass. A zero-collection monotonic store continues to fail even if its allocation loop becomes faster.
