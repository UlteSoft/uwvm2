# r10 / r11 GC A+B: first paired diagnostic plan

This plan has no candidate execution receipt. `A` is a preserved, source-bound
r10 build; `B` is the new r11 build after its actual runtime and CLI have both
built and its cold safety cases have passed. The keeper fills the bindings from
actual build receipts. An unbuilt candidate has no source ID, ELF hash or timing
in this document. Both products are compared within their own repository.

The candidate's two changes are collector root admission fused into marking
after unchanged graph prevalidation, and private compact-slot marking after a
fresh authenticated lookup inside the same exclusive paused cohort. Their
safety invariants are reviewed in the source design. These are hypotheses for
less duplicate work; this plan does not assert a measured benefit.

## Fixed inputs and admission

Pin the ordinary and ROS A/B source snapshots, canonical source fingerprints,
runtime objects, CLI ELFs, compiler and linker argv/sidecars, vendor trees and
LLVM/toolchain closure before and after every measurement window. Preserve the
A/B source diff. If r11 includes unrelated changes, report a build comparison;
do not attribute its whole difference uniquely to the two GC changes.

The six experimental macro values, all combine/delay values, LLVM target/flags,
GC collection threshold, function ABI and call-stack policy must match. For
the first round use `llvm-jit full`, `unwind`, EH phase `auto`, with the actual
same diagnostic argv except for the pinned executable path. Do not reuse a
runtime object across A/B. The experimental macros remain default-off outside
the frozen experimental builds.

Use exactly `gc-allocation-ring-512000000.wasm`, SHA-256
`4344aec55a95e51d86433ab6d57305528866f18583947a1def97e81b69d26d79`.
Its self-check checksum is `1687964949`. Each product sample must return zero
and report 512000000 allocations and committed slots, 125000 collections,
511998975 reclaimed objects and zero remaining pending numeric objects. The
same 1024-root ring, field/payload sequence, page/directory settings and
collection schedule must be used for A and B. Windows/source changes or a
different root count are different experiments.

Only the sole Linux keeper executes. The current scope stays 64GiB with zero
swap and CPUs `0,2,4,6,16-31`; the guest has one TID on P0. Compilation runs
separately on E cores and must fully retire before measurement. Authenticate
the current init/controller and owned children using actual PIDFD/birth,
ancestry, UID, executable, argv and exact target cgroup; no foreign process is
signaled. Keep the existing memory/CPU/owned-child/deadline guards. Temperature
is recorded only. Save boot/PMU/topology and the independent host P0/SMT
observer; unreadable or wide-affinity host activity is uncertainty, not quiet.

## Minimum sample order

Run one untimed cold safety/self-check per bound build first. This is not a
performance sample. Use fresh output directories and retain failed attempts.

| Evidence family | Ordinary order | ROS order | Minimum timed guests |
| --- | --- | --- | --- |
| No profiler | A, B, B, A | A, B, B, A | 8 |
| Pure grouped hardware counting | A, B, B, A | A, B, B, A | 8 |
| Collector/root-readback component | A, B, B, A for each duplicate cell | A, B, B, A for each duplicate cell | 16 native components, after its source-bound proof |

Within each family, A1/B1 and B2/A2 are the two matched pairs for one product.
Rotate which product goes first between families. Do not overlap the families,
VTune, QEMU, Windows compilation, another guest or a background own compiler.
Complete the whole guest even if observed temperature increases. Hard ownership
or resource failures still stop only the directly owned children.

Sample P0 frequency through the guest interval and retain every observation,
P05/median/P95, sample count, throttle counters and host sibling activity. Where
the CLI's execution-start/end markers can be aligned to telemetry timestamps,
report an additional Wasm-execution envelope; describe the timestamp alignment
and missing points. It is not an exact hardware-counter ROI. A pair whose
comparable interval's median differs by over 10%, that throttles, has too few
frequency samples, or has observed interfering activity remains raw diagnostic
data and is not a frequency-matched effect estimate. Unknown host activity
remains an explicit limit. Do not divide elapsed time by frequency to invent a
corrected benchmark result.

## Three measurement contracts

The no-profiler row records CLI internal Wasm time, whole guest wall time,
`wait4` user/system CPU seconds and maximum RSS, startup/JIT time if actually
reported, checksum/self-check, collection counters and raw logs. Divide the
internal or whole-guest time by 512000000 only as a whole-workload time per
step. Dividing by 125000 does not produce a collector pause latency: the
workload includes allocation, LCG arithmetic, table operations, casts, field
access, generated-code checks and collection.

The separate host counting protocol uses the actual P0 `cpu_core` type 4
group `{cpu_core/event=0x3c/,cpu_core/event=0xc0/}`, no software events, no
sampling, no system-wide collection and no inheritance. Actual enabled ACK
precedes guest GO; the original perf PIDFD receives SIGINT only after the guest
finishes. Preserve exact final guest event attributes, successful returned FDs
and the member-to-leader FD relationship. Cross-check actual JSON counts and
running time with raw verbose count/enabled/running, same exact group interval
and at least 99% running/enabled. Unsupported output is unqualified. Retain
counts, cycles/step, instructions/step, CPI and IPC alongside wall/guest CPU
time and frequency. These counts include ELF startup, initialization and JIT
compilation; they are whole-guest counts, never pure collector or Wasm-only
counters. The original frozen host entry accepts one immutable two-product
plan. The separate [four-build wrapper](run_current_host_pcore_gc_ab.py)
implements an explicit A/B contract without changing that entry or its
dependencies. Its source review and pure checks are not an actual A/B run.
Do not silently substitute a different binary into the original pinned plan.

VTune HW Hotspots/uarch is an optional follow-up on the measured regression or
gain. It uses separate samples and source-bound symbols/objects. State the
collection mode, event domain, running ratio/MUX, stack depth/skipped frames
and unknown JIT attribution. Its sampled self/inclusive CPU time and scaled
metrics cannot replace unprofiled elapsed time or exact perf-stat group counts.
The existing r9 VTune evidence cannot label r11 lambdas or establish r11 costs.

## Component boundaries

Use a separately built native fixture exercising the actual compact-numeric
allocation/page directory and root resolution used by these frozen products.
Keep its declared types/layout, generation sequence, 1024 roots, allocation
count, collection boundaries and directory/page configuration identical across
A/B. First prove readback payloads, stale-reference rejection, exact reclaimed
counts and surviving roots using independent expected values; allocation,
collection and readback timing cells are then separate. The old r2 explicit
sweep plan and legacy-header proof are not a compact-path qualification.
The existing `gc_explicit_sweep_ring.cc` uses mutable i32 fields and therefore
fails actual `compact_layout` eligibility even with the six macros enabled.
Do not use it to measure this compact-slot optimization. The independent
[gc_compact_collection_ring.cc](gc_compact_collection_ring.cc) instead declares
one immutable unpacked i32 field, creates the real canonical store and proves
every root with `compact_numeric_reader` before the first collection and after
every collection. All readers reset before the real exclusive admission.
Its [independent oracle](check_gc_compact_collection_ring.py) uses affine LCG
skips and checks observed payload sums, exact collection/reclaim counts and
the component-only boundaries. Source preparation and pure oracle checks are
not a native compile or execution PASS.
`test/0019.gc_statepoint/compact_collection_directory.cc` supplies additional
foreign-cohort, dead-token, duplicate-root and failed-collection safety cases;
its assertions do not provide a timed VM result. Include equal duplicate-root
patterns in A/B component controls so root admission and repeated marking
cannot silently measure different work.

Measure the collector API region alone and retain each returned status/count;
root arrays must already be constructed before the collection timer starts.
Measure root readback against independently tracked payloads in a separate
region, with observable checksums. Record allocation, collection, root-readback
and teardown time separately, as well as complete process wall/user/system/RSS.
Do not put logging, checksum formatting or RSS reads inside the measured
collector/readback region. If production adds counters, build that diagnostic
variant separately and do not mix its times with the uninstrumented product.
The native component cannot qualify VM root enumeration, JIT code, parked
mutators, exceptions or foreign-module lifetime safety.

The new native CLI is `COMPONENT allocations collect_every duplicate_roots`.
Inputs are bounded and allocations must be divisible by the interval. The
first component workload is 16777216 allocations, interval 4096, either zero
or 1024 duplicate roots in separate cells. It has 4096 ring collections plus
one final empty-root collection, reclaims all 16777216 objects and has zero
remaining objects. This native final drop differs from the VM's 125000
allocation-triggered collections and 1025 unreclaimed objects. Allocation
timing includes LCG, root publication and necessary status checks; collection
timing excludes admission acquisition/release and root snapshot construction.
The directory-enabled flag is reported by the actual compiled source and must
match across A/B.

## Report and stopping rule

Save each row's exact command, all inputs/hashes, exit/self-check/counters,
timing domain, raw frequency points and distribution, host observation, resource
receipt and raw logs under a new keeper evidence directory. Preserve unqualified
rows. A missing binding or safety failure blocks that A/B comparison rather
than borrowing a prior build's result.

For each product and evidence family report both matched B/A ratios, their
range and geometric mean; lower is better for elapsed time/cycles/instructions.
CPI/IPC must be accompanied by raw instruction/cycle totals because a lower CPI
alone need not mean less work. With two pairs do not publish a confidence
interval, tail-latency claim or industry ranking. Counter-family and unprofiled
ratios are separate; frequency or profiler overhead can differ between them.
An obvious regression returns to development with its raw attribution. A small
or inconsistent effect needs more pairs before an acceptance claim. Full Wasm3
safety/cross-platform acceptance remains a later gate.
