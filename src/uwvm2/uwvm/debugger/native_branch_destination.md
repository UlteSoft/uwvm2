# Owned MC direct control destination, private source proposal

This adds cold display DATA after the existing conservative owned-byte MC decode. A target-owned MCInstrAnalysis is retained with its same MCInstrInfo tables. The independent helper bounds opcode and BOTH exact MC/descriptor operand arrays before invoking evaluateBranch, requires one actual PC-relative immediate, checks signed scaling/addition and host/ISA width, and requires agreement with the target's actual answer. X86 uses instruction-end origin; AArch64 branch/call uses instruction-start plus a checked imm*4. Ordinary address-generating ADR/ADRP are excluded because this interface handles actual call/branch descriptors only.

Indirect register and RIP-relative memory calls have no direct callee target. The helper never evaluates a memory address, reads a register or requested target PC, symbol-resolves another function, constructs a host pointer or changes a native context. A branch's conditional marker does not tell whether it will be taken. Zero is a possible scalar destination, not readable memory authority. Overflow/invalid/variadic/inconsistent metadata, unresolved immediates, unavailable target analysis and target disagreement remain explicit unavailability.

The existing NI semantic veto and native platform qualification gates stay unchanged. A direct call target remains NI-unavailable until a separate genuine continuation stop exists; finish still needs actual caller CFI/stack-bound/owner proof. Native stop/thread/private capture/generation/epoch/code-range credentials are mandatory outside this DATA leaf. Console/controller/runtime APIs are untouched. Default LLVM-full emits no additional guest IR/TLS/poll; only a management decoder adds one optional analysis owner and scalar cold work.

Official LLVM23 source read: llvm/include/llvm/MC/MCInstrAnalysis.h evaluateBranch; llvm/include/llvm/MC/TargetRegistry.h createMCInstrAnalysis; llvm/lib/Target/X86/MCTargetDesc/X86MCTargetDesc.cpp X86MCInstrAnalysis::evaluateBranch; llvm/lib/Target/AArch64/MCTargetDesc/AArch64MCTargetDesc.cpp AArch64MCInstrAnalysis::evaluateBranch; llvm/lib/MC/MCInstrAnalysis.cpp default false implementation. Exact source hashes are frozen in the proposal manifest. The descriptor preflight is necessary: the target overrides index MCOperandInfo then call getImm and AArch64 scales a signed immediate.

Fresh component plan: real SDK same-source/header/provider/MC archive closure first, then compile native_direct_branch_destination.cc and execute only in keeper's 64GiB/swap0 cgroup. Tests decode genuine forward/backward call/conditional/unconditional branches, indirect register/memory calls, ordinary/return/truncated forms and checked address boundaries; malformed-MC test DATA exercises opcode/operand bounds against real target tables without executing those instructions. Repeat context retirement is checked. AArch64/Windows/macOS clauses are source only until their specific actual compiler/MC component observations; current Linux A64 product gates remain unavailable. Return77 is explicit unavailable, not a platform pass.

Fresh named-module consumer separately precompiles all real transitive debugger/provider partitions, new native_branch_destination plus dependent owned MC partition and aggregate; then compiles capsule and importer. Header inclusion is not a module qualification substitute. Existing decoded_instruction cold layout changed, so fresh all3 product TUs/BMIs are required for any later product integration. Native compilation/execution, disassembly console annotation, new hardware trap/NI/finish/address-break and performance are not qualified by this source proposal.
